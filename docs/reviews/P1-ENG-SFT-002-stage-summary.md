## 1. 一句话结论

在本仓库的 Unity 仿真九类车辆词表上，LoRA 微调让 Qwen3-VL-2B **完全学会了三态协议的输出格式**（609 行评估零解析失败，零样本有 103 行失败），单目标选框成功率相对同 prompt 零样本 **+26.6 pp**（`NON_INFERIOR`）；但**歧义报告**与**「不存在」拒答**两项没达门槛，功能门 **`GATE_NOT_MET`**；跨环境评估 `NOT_RUN(SFT_003_NOT_DONE)`。这是一次有限的协议适配实验，按合同以负结果如实交付，不授权追加训练。

## 2. 任务与数据（K4 候选 1，2026-09-14 … 09-18）

- **任务**：给定一帧与一句指令（`the taxi` / `the red car` / `the car to the viewer's right of the bus`），模型输出三态之一——`unique`（一个框）、`ambiguous`（全部候选框）、`none`（不存在）。九类词表只在 prompt 里给出，不是训练目标（「协议优先、词表靠 prompt」）。
- **数据来源**：仓库既有 Unity 采集（S3/S4/S5 归档，`P1-ENG-ASSET-001` 盘点后复用），gold 由对象真值离线派生，属离线数据加工；已绑定的红色动态目标车作为 `car` 候选入域。
- **训练集**：4,907 条不同图文样本 / 5,318 条多重集样本（歧义样本 ×2），3,198 帧；约 75% unique / 16% ambiguous / 9% none；训练池 = train∪dev 七族减 `detect-scout1`。
- **选层集**：441 行（unique 300 / ambiguous 41 / none 100），只用于三配置选优。
- **评估集**：S4 test 冻结 609 行，与训练∪选层按帧 SHA 零交集：G1 单目标 210、G2 颜色 49、G3 歧义 48、G3′ 灰区诊断 50、G4 关系指令 86、G5 不存在 100、目标车子组 G1t/G2t/G3t 23/23/12、LEGACY_ONLY 8；旧探针 405 行 legacy 逐行守恒。
- **标签抽查**：用户看图 21 张（含 3 张复判），2 张颜色判「错」裁定为上游标签缺陷并整帧排除对应颜色指令；框为 amodal 投影 AABB，标记 `UNVERIFIED`。
- **token 预检**：同版 tokenizer 对全部 gold 逐条实测，max 87 ≤ 152 拒绝阈值。

## 4. 评估结果（609 行；微调 C2 vs 同 prompt v2 零样本 base）

**表 G 判定**：功能门 `GATE_NOT_MET`（5 项通过 1 项）；词表非劣 `NON_INFERIOR`；跨环境 `NOT_RUN(SFT_003_NOT_DONE)`。

| 层 / 组 | 零样本 | 微调 C2 | 门槛 | 结果 |
|---|---|---|---|---|
| 解析失败（609 行） | 103（截断 31 + 格式错 72） | **0** | — | 格式完全达成 |
| G1∪G2 单目标 Success（259 行） | 51.0% | **77.6%** | 非劣 ≥ −2 pp | **+26.6 pp**，bootstrap CI [20.5, 32.8] |
| (a) G3 歧义报告率 / 严格成功（48 行） | 0 / 0 | 39.6% / 25.0% | ≥ 70% / ≥ 50% | 未达 |
| (b) G1∪G2 误报歧义 | 0 | 2.3% | ≤ 10% | 通过 |
| (b) G1∪G2 误报 none | 30.1% | 11.6% | ≤ 5% | 未达 |
| (c) G5 none 率（100 行） | 76.0% | 79.0% | ≥ 80% | 差 1 行 |
| G1 单目标（210） | 51.4% | 76.7% | 不入门 | +25.2 pp |
| G2 颜色（49） | 49.0% | 81.6% | 不入门 | +32.7 pp |
| G4 关系指令（86） | 8.1% | 82.6% | 不入门 | +74.4 pp，提升最大 |
| G1t / G2t 目标车（23 / 23） | 39.1% | 65.2% | 不入门 | +26.1 pp |
| G3t 目标车歧义（12） | 0 / 0 | 报告 41.7% / 严格 0 | 不入门 | 报告率升、严格成功仍 0 |
| G3′ 灰区诊断（50） | 报告 0 / 命中任一 M 69.6% | 26.0% / 84.8% | 诊断 | — |

**分层（微调）**：S 层最弱——G1 S 36.7%（M 81.1%、L 85.9%）、G3 S 严格成功 14.3%、G4 S 72.7%；按类别 car 最弱（G1 35.0%、G2 40.0%、G4 42.9%），suv / taxi / police car 在 90% 以上；unseen 行（G1 30 行 96.7%）分母小、不作解释。

**旧探针 v1 对照（诊断附表，345 行可比）**：旧 prompt v1 探针 73.0% → prompt v2 零样本 40.3% → 微调 78.8%。即 prompt v2 零样本本身比 v1 探针差很多（格式约束更严），微调把它拉回并略超 v1。

## 5. 失败画像（只描述，不作因果结论）

1. **歧义不报，且只会报「两个」**：G3 48 行里 29 行直接答 `unique`（其中 25 行的框与某个 gold 成员 IoU ≥ 0.5——模型挑了一个候选而不报歧义）；报了歧义的 19 行**全部恰好给 2 个候选**，gold 为 3 个的 5 行都少报一个。训练集歧义样本 411 条中 401 条是 2 候选、10 条是 3 候选。G3 的 TP/FP/FN：0/34/103 → 36/31/67。
2. **误报 none 集中在贴边框**：G1∪G2 的 30 行误报 none 里 25 行 gold 贴画面边缘（贴边 134 行漏报 18.7%，不贴边 125 行漏报 4.0%）；gold 是 amodal 投影框，贴边对象在画面里可能只露出一部分，本报告不判定是标注还是模型的问题。
3. **错框**：G1 15 行答 `unique` 但 IoU < 0.5（11 行 IoU < 0.1，框落在目标之外）；G2 7 行；G4 11 行。
4. **G5 误报**：100 行里 21 行把不存在的类别答成 `unique`（pickup truck 5、police car 4、car 4、truck 4、ambulance 2、bus 1、suv 1）；police car、ambulance 的拒答率反而低于零样本。与零样本逐行比：只有微调答对 12 行、只有零样本答对 9 行。

## 6. 这个结果能说明什么、不能说明什么

- **能说明**：在本 Unity 场景、九类词表、prompt v2 协议下，约 2 GPU 小时、$1.72 的 LoRA 微调足以让 2B 模型稳定输出协议格式，并把单目标与关系指令的选框成功率提高到 77–83%；歧义与拒答的短板是数据构成问题（歧义候选数分布、none 硬负例、贴边 gold）而非算力问题。
- **不能说明**：+26.6 pp 不能读作「定位能力提高 26.6 pp」——对照的零样本有 103 行解析失败，相当部分提升来自格式遵从（v1 对照只 +5.8 pp）；不主张真实航拍、开放词表、跨环境泛化（SynDrone 未跑）、跟踪性能、恢复能力或 Jetson 性能；不能区分「两辆一样的车里哪辆是原来跟的」（模型无历史身份输入）。
- **统计限制**：单种子、每组一次 greedy、未做重复运行；5 Hz 近重复帧多，行级 CI 只是描述性区间；gold 为 amodal 投影 AABB（`UNVERIFIED`，S6 未审计）；test 帧曾被旧探针读取过做零样本推理，作独立留出的证据力有限。
