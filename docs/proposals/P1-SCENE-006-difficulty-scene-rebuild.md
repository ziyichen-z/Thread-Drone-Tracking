## 3. 算法或行为假设

### 3.1 一个必须先承认的不相容

以下为**针孔代理上的候选搜索论证**（R8：非门判据；门见 §5.1）。在当前
冻结传感器配置（`vertical_fov_deg = 60`、`h = 25 m`）下，"探测器可尺寸"
与"指向构成约束"的代理条件**不可兼得**：

- 针孔车高 `≥ 21 px`（预筛代理线，量级对齐 SCENE-004 资源门的 25 px
  `min(w,h)`，针孔高恒 ≥ 投影 min 边，故该代理偏松）要求斜距
  `≤ 30.68 m`；
- 指向构成约束（离轴 `> 45 + 30 = 75°`）要求水平 `> 93.30 m`，即斜距
  `> 96.59 m`。

`30.68 < 96.59`，差约 3.15 倍——且代理偏松只会让真实门更难，不相容结论
在真实门下只强不弱。**所以"把路线拉远制造难度"这条路在现有
光学下走不通**——拉远到指向受限时，目标已经小到探测器完全失效，正是
现路线远端 `8.77 px` / `recall 0/45` 的处境。

### 3.2 可行域确实存在：FOV 与高度是 §6 明列的可变参数

`limit = maximum_off_nadir_deg + vertical_fov_deg / 2`，而
`fy = (H_px/2) / tan(vfov/2)`。**收窄 FOV 同时**降低 `limit`（指向更早
受限）**并**提高 `fy`（像素更大）——两个方向同时有利。取恰好越过指向
极限处的车高像素：

| vfov | h (m) | limit | 需水平 (m) | 斜距 (m) | 针孔车高 px（代理） | 代理可行 |
|---|---|---|---|---|---|---|
| 60 | 25 | 75.0° | 93.30 | 96.59 | 6.67 | — |
| 60 | 10 | 75.0° | 37.32 | 38.64 | 16.68 | — |
| 45 | 15 | 67.5° | 36.21 | 39.20 | 22.91 | **OK** |
| 30 | 25 | 60.0° | 43.30 | 50.00 | 27.77 | **OK** |
| 30 | 15 | 60.0° | 25.98 | 30.00 | 46.28 | **OK** |
| 20 | 25 | 55.0° | 35.70 | 43.59 | 48.40 | **OK** |

这是**代理层面的存在性证明**，不是设计选点，也不是 T1/T1′ 通过证据。具体取值由接受角色裁定；本提案的立场
是优先动 FOV（单参数、影响面明确、双向有利），高度与锚点位置作为次级
调节量。

### 3.3 遮挡与指向是两条独立通道

§3.1/§3.2 只处理**指向**通道。§6 要求的"加入遮挡与干扰车辆"是**另一条**
通道，与 FOV 无关，其效果只能由射线检测测得。两者都要有，且在验收判据
中分别计量（§5.1 的分解量），不得混为一个总分。

### 3.4 锚点重定位是主方向（更正对 SCENE-003 的误读）

**本节更正本提案早期口径。** `P1-SCENE-003` 的 `BLOCKED_ANCHOR_PLACEMENT`
**不是**"草地不在允许清单里"。冻结配置
`config/p1-scene-003-anchor-placement.json`
（`sha256=edb9d646…81b1`）的允许清单恰恰包含草地：

```json
"support_surface_allowlist": ["Natures_Grass Tile", "Natures_Grass Tile Small"],
"support_height_tolerance_m": 0.05
```

真正的失败是**高程不匹配**：草地瓦片实测支撑面高程约 `0.0000013 m`，而
当时冻结的候选锚点高程沿用了现锚点的 `0.2 m`（现锚点坐在路面上），
`|0.2 − 0.0000013| = 0.2 > 0.05`，1,257 个候选全部报
`SUPPORT_HEIGHT_MISMATCH`。支撑门在净空门之前，所以工件如实报告零次净空
评估。

这是一个**很窄且可复查的冻结假设**，不构成锚点重定位不可行的证据。让候选
锚点高程跟随实测支撑面高度（草地上约 `0`）而非沿用 `0.2`，该阻塞很可能
直接解除——但这必须由实测审计判定，本提案不预断。

因此本提案改为**以锚点重定位为主方向**，理由见 §3.5 的量化对比：它把
`ANCHOR_ROUTE_CONFLICT` 从根上消掉，同时把 `2.94×` 的距离跨度塌缩到
`1.20×`。

### 3.6 初始化可观测性：用户建议的合法形式（R14 重定义）

用户提出"写一个函数让无人机始终出现在车辆上方，保证初始化不会有问题"。
底下的需求成立，但**字面形式不能实现**，三条理由：

1. **真值泄漏**。运行时把机身钉在目标上方，控制器必须读目标真值位置。
   `CLAUDE.md` 与设计 §6 的边界纪律是"Unity 真值只允许进入
   `CoverageEvaluator`，严禁进入控制器、感知输入或对外传感器元数据"。
   一个跟随真值的控制器会让它产出的每一个覆盖率数字失效。
2. **会消灭研究问题**。机身若被 oracle 粘在目标上方，`C_geom ≈ 100%`，
   M3′ 三条策略再次退化为一点——比当前场景更糟。
3. **几何上对任何合法候选都做不到（R14 更正）**。`p_hover` 冻结在锚点
   正上方（§5.2），而 T5 要求锚点到路线最小水平距离 `≥ 1.5 m`——所以
   **任何**通过 T5 的场景里 `p_hover` 都不在路线正上方；建议设计点该
   距离是 `27.5 m`。原稿"机身可以真正位于路线最近点正上方、把初始离轴
   压到 `0°`"的推论**错误，本稿撤回**：`r(20) = 28.72 m ≥ 27.5 m` 只
   证明系留工作空间**另有**站点可达路线上空（该事实归 T4 站点集合），
   `t = 0` 时机身在 `p_hover`，初始离轴代理值为 `atan(27.5/20) =
   53.972627°`，不是 `0°`。

**需求本身是真的**：DETECT scout-1 实测远端 recall `0/45`，若一次运行从
远端起步，首帧视觉提示会直接失败。这正是"初始化有问题"的实际形态。

**合法形式是把它变成放置期的初始条件，而不是运行期的控制律，且在固定
`p_hover` 上定义**（R14 选项 (a)。弃 (b) 的理由：独立 `p_init` 需要新的
机身放置机制、新配置字节、放置期守卫扩展和进入 `p_hover` 的转移证明，
把静态筛查变成带机动的运行协议；且如上第 3 条，`p_init` 位于目标上方
对任何合法候选都与 `p_hover` 不同点，该机制对每个场景都必需——(a) 则
零新机制）：

> **T6 — 初始化可观测性（R14 重定义，固定 `p_hover`）**：冻结初始目标
> 相位 `s_init = argmin_{s ∈ [0, 周长)} offaxis(p_hover → 路线点(s))`
> （平局取较小 `s`；建议设计点即路线最近点）。在 §5.2 冻结策略下扫描
> `k ∈ [0, K_acq]`、**`K_acq = 10`**，取
> `k* = min{k : V(s_k) = 1}`（§5.1 谓词——与 evaluator 逐点等价，
> §5.3 保真门；`p_hover` 构型，视锥 + 射线）。
> **门 = `k*` 存在，且 `s_{k*}` 帧真实 `min(w, h)` `≥` T1 样本域
> （§5.2 第 8 条）的中位数**（与 T1 同一投影口径）。**`K_acq = 10` 是
> 预注册工程窗口（R21）**：取值动机是静止 desired 的追赶步数
> `⌈180°/24°⌉ = 8`（§5.2 第 4 条）加 2 步裕量；但目标在窗口内仍按
> `Step` 移动、desired quaternion 随之变化，该静止追赶界**不构成**对
> 运动目标的必达证明——原稿"8 个样本必达、因此 T6 失败只能因为目标
> 真的不可采集"的主张**撤回**。T6 失败时工件按 `k` 逐样本报告视锥与
> 射线判定，失败归因交接受角色，不预设原因。

**T6 是 Editor 离线候选门，不主张任何运行时接线（R19 选项 (a)）。**
原稿"落实机制已经存在、把参数 `s_init` 冻进配置即可在正式场景首帧前
生效、不需要新函数"的运行时主张**错误，本稿撤回**：真实

### 5.4 T4 见证路径证书（R4 + R11：唯一冻结构造）

端点落在系留球内加一个时间上界**不构成**合法动作证明。每个候选站点
`p` 的证书按以下**唯一冻结构造**生成与判定：

1. **路径形状**：`p_hover → p` 的直线段。两端点都在系留球（凸）内，故
   全段在球内；高度线性插值，两端都在 `[8, 32] m` 带内故全段在带内——
   这两条按凸性构造成立，写入证书但无需逐点验。
2. **速度剖面**：沿线段的 rest-to-rest 梯形剖面，`|v| ≤ 4.0 m/s`、
   `|a| ≤ 4.0 m/s²`；时长解析给出，计入证书（不参与任何门阈值）。
3. **净空证书（保守离散，R17 修正）**：取 `N = ⌈len/δ⌉`（`δ =
   0.25 m`、`len` 为线段长），在 `u_i = i · len/N`（`i = 0 … N`，
   **含两端点**）采样——相邻间距 `≤ δ`，故路径上任一点到最近样本的
   距离 `≤ δ/2`，该上界对端点与末段同样成立。每个采样位置做：
   (a) **机体球净空**：半径 `1.0 + 0.5` m Minkowski + 采样间隙膨胀
   `δ/2 = 0.125 m`，合计 `1.625 m`；
   (b) **系留线胶囊净空**：锚点到该位置，名义半径 `0.25 m` + **同一
   `δ/2` 膨胀，合计 `0.375 m`**（R17：机体与系留同享连续性论证——
   直线路径上 `B(t)` 距最近样本 `B_i` `≤ δ/2` 时，段
   `anchor → B(t)` 上参数 `τ` 处的点距段 `anchor → B_i` 同参数点
   `τ · |B(t) − B_i| ≤ δ/2`，故 `0.375 m` 半径覆盖两样本间全部中间
   系留构型）。
   任一采样违规即证书失败。
4. **锚点端支撑修剪（R17 独立重导，单一算法）**：本 ID **不沿用**
   SCOPE-002 的 `d_trim = 1.0 m`——该提案三轮均未接受（不存在"已
   确认"），其 round 3 恰好退回了 trim 算法；且新锚点 support y ≈ 0
   时 `1.0 × sin(13.212980°) = 0.2286 < 0.25`，1.0 m 修剪连名义半径
   都不能证明离开支撑面。按本 ID 的 support-relative 几何独立重导：
   站点集合最小系留仰角 `θ_min = atan(8 / sqrt(35² − 8²)) =
   13.212980°`（`h = 8 m` 层最大半径 `34.0735 m`；仰角 `≥ θ` 的点集
   是凸锥，直线路径两端点在锥内则全程在锥内，故 `θ_min` 同时是全部
   站点和全部转移路径的下界）。胶囊中心线在距锚点 `d` 处离支撑面高度
   `= d · sin(θ_min)`；取 **`d_trim = 1.70 m`**，则
   `1.70 × 0.228571 = 0.388571 ≥ 0.375`，修剪段外的膨胀胶囊在任何
   合法构型下都不可能触及支撑面，命中即真实违规。算法唯一：头段
   `[0, 1.70 m]` **照常查询全部 collider，只忽略唯一实测支撑实例**
   （以 T5 审计记录的 instance ID 绑定）、其余命中照常失败；余段
   `(1.70 m, len]` 不忽略任何实例。
5. **判定**：证书失败的站点**不进入 `max_p`**，并按"机体拒绝/缆绳拒绝/
   路径拒绝"分类计数写入工件；不许沉默剔除。

T4 继续只是候选场景预筛；证书不用于关闭 BC-M34-4(b)。

## 6. 基线、消融、失败模式和资源风险

### 6.1 对照

- **现冻结路线**：`0.0000` 出视锥占比、远端 `8.77 px`——两端都失效的反例；

### 6.2 失败模式

| 模式 | 表现 | 处置 |
|---|---|---|
| T1 与 T2 仍不相容 | 找不到同时满足的参数组合 | §3.2 已证可行域非空；若实测仍不相容，说明遮挡代理或谓词实现有误，fail closed |
