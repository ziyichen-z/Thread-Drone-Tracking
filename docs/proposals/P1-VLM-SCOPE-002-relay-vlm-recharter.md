## 1. 问题和研究价值

### 1.1 应用场景

场馆/园区周边的长航时系留监控：系留机可达域固定（35 m 缆、8–32 m
高），单机无法跟随目标离开其可达域；两台及以上系留机在可达域边界
**接力**，操作员在环。这是用户 2026-07-21 的原始目标（双机接力 +
小模型边缘部署），VLM 通信是接力的介质而非附加物。

### 1.2 现状：小脑的方向性描述（非门状态）

下表是对反射层 + 规划层能力的**方向性描述**，不是任何门的状态；正式
门状态以状态板 Gate board 为准（M3′ 未关闭，M4′ 以后未启动）。

| 部件 | 方向性描述 | 依据 |
|---|---|---|
| NanoTrack + LOS 云台跟踪 | ≤ 64° 离轴可靠 | qual-3 `C_track\|geom = 0.92`；O1 臂 B 全程 1.00 |
| YOLOE 三门重锚定 | 在 benign 载体有效；**主环线上哑** | O4 |
| 世界系 EKF | 可用；协方差在云台饱和时过自信 | 臂 A `nees_median ≈ 1017`，臂 B ≈ 4.8（状态板登记发现） |
| 阈值式机身分配 + 系绳净空 | 可用；被动反应式、被锚点旁街道家具限制 | O7 |
| 帧桥 / 协议 / 评测器 / run 基建 | 稳定 | `P1-M0-001` 等 `DONE` |
| **知道自己跟丢了** | **无** | O3、O4 |
| 丢失后搜索（L2a/L2b） | 无（M4′ 未开工） | — |

三件事决定了单机做不完这个任务：(a) 可达域之外必丢（O1）；(b) 小脑
不知道自己丢了（O3/O4）；(c) 丢了之后没有任何东西把目标交给别人。
三件事都不是遮挡问题，是**接力问题**。

### 1.3 研究主张（三层，提请写入设计 §1）

> **T1（接力跟踪效能，B2 支撑；revision 2 收窄为端到端栈比较）**：
> 在固定锚点、有限缆长的多机系留监控中，当目标在各机可达域之间移动
> 时，**语言端到端交接栈**（P 的模板文字 + 接收方帧 + VLM grounding）
> 相对**结构化端到端交接栈**（P + 规则重检测），在同一载荷生成源 P
> 与 §5.4 裁决结构下，主终点是否非劣/更优。**不主张把差异严格归因于
> 语言介质本身**——两栈的接收输入与解码算法都不同；介质层面的机制
> 证据由 §2.6 的分解诊断提供，只作描述。开放词汇描述（信息优势臂，
> 明标非同信息）单列，只报相对差。
>
> **T2（操作员通信正确性，B3 支撑）**：操作员改令/询问/主动汇报在
> 脚本化、可评分的协议下的正确率、延迟与误报率；**不主张**其提高
> `C_track` 或 MTTR。
>
> **T3（展望，不作主张）**：交互能力的 verified distillation 与边缘
> 部署。在其自有提案给出可证伪成功条件之前，本章程只把它写成展望；
> `P1-M7-DEPLOY-001` 维持 `OUT_OF_CURRENT_SCOPE`。

定位约束：SOT / YOLOE / 具体 VLM 型号仍是实现组件；贡献本体 =
(a) 固定锚点系留监视中的动态目标所有权交接协议及其同源载荷的栈级归因评估；
(b) 操作员在环的任务级通信协议。真值边界不变。

### 2.2 大脑职责

任务状态机（所有权、L0–L4、交接态）／交接决策与消息（VLM：描述、
核验、反问）／操作员接口（汇报、询问、改令）／学习回路（仿真真值
验证后蒸馏，T3 展望）。

### 2.3 四条架构原则

1. **慢、离散、可验证**：大脑只输出带 `valid_until` 与幂等 `msg_id`
   的离散决策/消息；小脑不等大脑；**大脑不向在跟的快环注入像素框**
   （接收方 ACQUIRE 是例外，见 §2.7）。延迟预算按几何算：共视区停留
   时间（O6：≈ 14 s）。
2. **丢失由几何推断**：不信 tracker 的 `TRACKING`；用估计位置 +
   道路先验 + 可达域预测「将在 t 离开 A、t+Δ 进入 B」。
3. **两栈同源载荷**：语言臂与结构化臂由**同一规范语义载荷 P**
   （§2.6）确定性生成——等化的是发送方承诺传递的信息源，不等化
   接收端解码算法（T1 因此只作端到端栈比较，revision 2）。超出 P 的
   开放词汇描述单列信息优势臂，不称同信息。
4. **真值边界不变**：大脑可见 = 帧、小脑状态、静态道路/地标表
   （两机、VLM、规则对照读同一 hash）；不可见 = evaluator 真值。

### 2.4 接口（草案，细化归下游实现提案）

沿用设计 §2 五接口；新增：

```
MissionState   { drone_id, target_id, ownership_epoch, owner_drone_id,
                 tracking_state, handoff_state, lease_until, seq,
                 last_msg_id_seen[] }                        # 持久化，见 §2.5
OwnershipRecord{ target_id, current_epoch, owner_drone_id,  # 权威源（AR1-1）：
                 msg_id, updated_at }                       # 共享单文件，原子 rename
HandoffMessage { msg_id, target_id, ownership_epoch,        # epoch = fencing token
                 from_drone_id, to_drone_id, issued_at, valid_until,
                 kind: OFFER | ASK | ACK | CONFIRM | NOTIFY_GRANT,
                 payload: P,                                # §2.6；两臂字节相同
                 rendering: { arm: LANGUAGE | STRUCTURED | OPEN_VOCAB,
                              text: str | null } }          # 语言臂/信息优势臂的文字
```

`target_id` 使既有单目标协议向 B3 改令与多目标演进兼容；
`ownership_epoch` 是每 `target_id` 单调递增的 fencing token，所有
对外发布（观测、云台/机身指令、消息）都携带它，消费端拒绝旧 epoch
（防崩溃恢复后的旧 owner 分裂行为）。

`source_drone_id` 进入帧包与观测协议（协议改动 → 强制停点）。

### 2.5 所有权协议（共享权威文件 + epoch fencing；revision 3 按 AR1-1 重写）

**环境假设（声明）**：两机控制器是同主机上的两个进程，共享同一
文件系统（既有文件桥）；故障模型为 **crash-recovery**（进程可在任意
指令处死亡并可重启，无拜占庭行为）；POSIX 原子 rename 与 fsync 语义
成立（项目既有 `AtomicFile` 前提）。

**全局权威源**：每个 `target_id` 一个共享文件
`runtime/mission/<target_id>/ownership.json`（`OwnershipRecord`，
§2.4），**只能通过临时文件 + fsync + 原子 rename 更新**。任意时刻
读者看到旧版或新版，绝无中间态——**该文件就是仲裁，两机日志只是
各自的账**。

- **提交点（唯一线性化点）**：A（当前 owner，epoch `e`）校验 B 的
  `CONFIRM` 在 lease 内且 epoch 匹配后，**原子 rename 写入
  `{current_epoch: e+1, owner: B}`——rename 完成即所有权转移**。
  写者纪律：rename 前重读权威文件并确认 `current_epoch == e ∧
  owner == self`，否则放弃（自己已被推翻）；只有权威文件指名的
  owner 允许写下一次转移，故障模型无拜占庭，单写者不变量成立。
- **fencing（全局可执行）**：所有任务级发布（交接消息、任务报告、
  所有权标记的观测行、mission 日志行）携带 `{target_id, epoch}`；
  每个消费者在消费前读权威文件，**拒绝 `epoch < current_epoch` 并
  计数 `STALE_EPOCH_REJECTED`**；发布者在每次任务级发布前重读权威
  文件——被推翻的旧 owner 至多发出一次将被拒绝的发布即自我降级。
  各机对**自身平台**的云台/机身指令不跨机、不受 epoch 门限制
  （观察者也可指向目标），但 planner 的任务级模式（追踪/待命）随
  角色切换。
- **三种角色（AR1-1）**：**语义 owner** = 权威文件在当前 epoch 指名
  的机，唯一可发起 OFFER/转移、唯一以 owner 身份发任务报告；
  **观察者** = 任何在跑 SOT 并发布 `role: observer` 观测的机（受限
  双跟踪期两机皆是）；**commander** = 为任务目的机动自身平台的机，
  本系统中 commander ≔ owner（各机只指挥自己的平台），被降级的机
  planner 回到待命站位。
- **`PREPARED`（接收方，`CONFIRM` 前持久化）**：B 在发 `CONFIRM` 前
  fsync `PREPARED{msg_id, target_id, epoch, candidate_box,
  source_frame_id, replay_state_sha256, valid_until}`。崩溃恢复：
  权威文件已是 `{e+1, B}` → 以 owner 身份按 `PREPARED` 恢复锁定，
  不可恢复则以 owner 身份如实申报丢失（终态
  `HANDOFF_LOST_AFTER_TRANSFER`）；权威仍是 `{e, A}` 且 `PREPARED`
  未过期 → 幂等重发 `CONFIRM`；已过期 → 丢弃并记 `PREPARED_EXPIRED`。
- **`NOTIFY_GRANT` 只是通知**：B 的所有权来自权威文件，不来自消息；
  `CONFIRM` 重试超时的兜底是**读权威文件**，故「GRANT 丢失」不产生
  歧义终态。
- **提交前故障枚举**（权威仍 `{e, A}`）：`CONFIRM`/ACK 丢失 → 重试；
  重试耗尽或 lease 到期 → `HANDOFF_TIMEOUT`，A 仍 owner，B 弃候选；
  A 崩溃 → 恢复后读文件仍 owner，继续或放弃本次 OFFER；B 崩溃 →
  `PREPARED` 路径。
- **提交后故障枚举**（权威已 `{e+1, B}`，**所有权不回滚**）：A 崩溃
  → 恢复后读文件即自我降级；B 崩溃 → `PREPARED` 恢复路径，最坏以
  owner 身份申报丢失；A 正常而通知未达 → 保持观察者跟踪至看到 B 的
  首次 owner-epoch 发布或 `T_handover_grace` 到期后转待命。
- **无见证崩溃**（副作用与见证之间死亡；权威文件因 rename 原子性
  不在此列）：沿用 SCOPE-001 round 4 §16 第 1 条——只记
  `CRASH_OUTCOME_UNKNOWN`，该次交接计失败、`msg_id` 永久作废、禁止
  重放；预注册崩溃注入矩阵覆盖每个耐久边界（含提交前后 A/B 各注入
  点；继承 CAL-001 E3，缩窄到本协议）。
- **逐消息持久化顺序**：发送侧 ① fsync 意图记录
  `{msg_id, kind, target_id, epoch, payload_sha256}` ② 原子写消息
  文件 ③ ACK/超时后记结果；接收侧 ① 校验 epoch/`valid_until`/去重
  ② fsync 受领（`CONFIRM` 前另须 `PREPARED`）③ 行动。
- **幂等/过期/重试**：`msg_id` 去重表持久化；过期消息拒绝并计
  `STALE_REJECTED`，被采纳者计 `STALE_ADOPTED`（目标 0）；ACK 超时
  指数退避至多 `N_retry` 次。
- **运行时安全指标（AR1-1 硬门化，按真值/日志离线判定）**：
  `DOUBLE_COMMANDER_ACCEPTED = 0`（同一目标、重叠有效期内被消费端
  接受的两个不同 owner 的任务级发布）；`ZERO_ACTIVE_OWNER`（权威
  指名的 owner 超过 `T_heartbeat` 无有效发布）时长恒 0，注入崩溃的
  场次除外且须与注入点一致；`WRONG_TARGET_TAKEOVER = 0`；
  `STALE_ADOPTED = 0`；`DOUBLE_TRACKING`（设计内）逐次 ≤ lease 封顶。
  **权威文件恒有 owner 是日志性质，不得用来掩盖运行时无有效执行者**
  ——运行时安全由 `ZERO_ACTIVE_OWNER` 与 `DOUBLE_COMMANDER_ACCEPTED`
  两个行为指标承担。
- canonical JSON：RFC 8259 strict、`allow_nan=false`、数值有限（沿用
  BC-P2-10 先例）。

### 2.6 规范语义载荷 P 与三臂定义（revision 2：栈比较 + 分解诊断）

`handoff-payload/v1`，B2 采集前冻结 schema 与量化档；**两臂的 P 字节
相同**，由发送方小脑状态确定性导出，不含评测真值：

| 字段 | 取值 | 来源 |
|---|---|---|
| `t_ref` | 发送方最后一次**在路**观测的 `capture_monotonic_s` | 两机共用 `system-stopwatch/v1` 时基（同一 Unity 进程） |
| `road_segment_id` / `offset_bucket` | 冻结 `WorldModelHandle` 道路面 id + 沿路里程 5 m 档 | 估计位置投影到道路面 |
| `heading_8way` / `speed_bucket` | 八分区；`{STOPPED, SLOW, NORMAL, FAST}` | 估计速度量化 |
| `appearance` | 闭集词表：`color`、`class`（与 B3 改令词表同源） | 任务下达时冻结的目标定义，非在线识别 |
| `uncertainty_bucket` | `{TIGHT, LOOSE, STALE}` | 膨胀后协方差迹量化 |
| `expected_entry` | 预计进入接收方可达域的 `road_segment_id` + 时间档 | 估计外推 + 可达域几何 |

三臂定义：

| 臂 | 发送方产物 | 接收方输入 | 接收方获取目标的方式 | 主张层 |
|---|---|---|---|---|
| 结构化臂 | P | P | 规则：`road_segment` 几何门 + `appearance` 闭集色块过滤（ACQUIRE 原语，`P1-RELAY-001`）→ 锁定 | T1 结构化端到端栈 |
| 语言臂 | P 的**冻结模板文字化**（确定性，零 API） | 文字 + 本机帧 | VLM 解析文字并在本机帧中 grounding → 锁定 | T1 语言端到端栈 |
| 信息优势臂 | VLM 看发送方帧自由描述（可超出 P） | 文字 + 本机帧 | 同上 | 单列，**不称同信息**，只报对上两臂与 oracle 的差 |

**分解诊断（描述性，不进 T1 主张；大部分并入 B0）**：
① 解析保真度——语言臂文字 → `P′` 的字段级还原率（模板可逆，预期
近 100%，坍塌即报）；② grounding 条件成功率——同一接收帧上
「给 P 的规则锁定」vs「给文字的 VLM 锁定」各自的成功率与失败模式
分型；③ 端到端差 = ①②与消息时延的合成。三项定位机制，不支持
「归因于语言介质」的因果句式。

**接收适配器可见字段白名单（AR1-4，采集前冻结并测试强制）**：

| 臂 | 适配器可读 | 机械禁读 |
|---|---|---|
| 结构化臂 | `payload P` + 本机帧 | `rendering.text` |
| 语言臂 | `rendering.text` + 本机帧 | **`payload P`**（消息中保留仅作 provenance/审计） |
| 信息优势臂 | `rendering.text` + 本机帧 | `payload P` |

隔离机制：适配器入参只含白名单字段（构造时剥离），另加源码扫描
测试断言语言臂路径零 `payload` 引用——先例 BC-M34-3 的
`del estimate` + 扫描测试。「双向」表述随标题更正：机↔机 =
**VLM 介导的单向描述语言 + 结构化控制消息**（`ASK` 为闭集，不计入
自然语言对话主张）；**双向自然语言只在操作员通道（B3/T2）主张**。

结构化臂的精确估计/协方差/外观嵌入**不再进入消息**；这些量只用于
发送方自身的 `expected_entry` 推导与离线分析。

### 2.7 接收方 ACQUIRE 的 replay 合同（回应外部审查第 2 条）

接收方 grounding 得到的框对应某个源帧；锁定必须在源帧上初始化 SOT
并沿帧缓冲重放到当前（既有 DETECT 重提示通道：`frame_buffer_s = 6.0`，
`catchup_timeout_s = 2.0`）。接收方没有受保护的在跟目标，故 ACQUIRE
的最大结果年龄 `acquire_max_age_s` 是独立参数，上界为帧缓冲长度，
**数值由真实 `replay_tracker()` 路径实测导出**（继承 CAL-001 E2，
缩窄到 ACQUIRE 路径；TRACK-002 的 update-only 常量只作交叉检查）。
超过年龄或追赶超时 → `ACQUIRE_STALE`，回到 §2.5 的重试/终态。

3. **B1**：B1a——n 机评测器在单机配置下与旧评测器逐帧一致（回归）；

4. **B2（T1 所在；裁决结构本稿冻结，数值由 B2 提案采集前冻结且不得
   由本批数据反推，R2-4）**：配对单位 = 同 seed 的单机 hold 臂 /
   结构化臂 / 语言臂各一次。**裁决顺序**：
   (i) **安全硬门**（任一不过则该臂整体判失败，不得以效能弥补）：
   `STALE_ADOPTED = 0`、`WRONG_TARGET_TAKEOVER = 0`、
   `DOUBLE_TRACKING` 逐次 ≤ lease 封顶、`ZERO_OWNER = 0`（崩溃例外
   单列并如实报告）；
   (ii) **主终点（唯一，AR1-2）**：**交接事件窗口内联合正确身份
   覆盖率** `C_track^W` 的同 seed 配对差（语言栈 − 结构化栈）。事件
   零点 = 目标**真值里程**穿越预注册交接区边界（纯几何，逐 seed
   确定，跨臂恒同，与是否发出 `OFFER` 无关——不可被「不发起交接」
   规避）；窗口 `[t0 − a, t0 + b]` 的 `a`/`b`、每 seed 事件数
   （名义每圈 2 次）与聚合方式（先逐事件、再逐 seed 配对）随 `δ`、
   seed 数 `N`、配对 bootstrap 95% CI 方法一并由 B2 提案在采集前
   冻结；窗口按日程全量计分，**无删失**——协议失败（超时/孤儿）的

   接力」，更优才可称「有效」；否则如实报「语言 ≈ / < 结构化」

Decision: **REVISION_REQUESTED**

Rationale:
