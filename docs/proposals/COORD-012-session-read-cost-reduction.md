## 1. 问题与证据

COORD-007 砍的是裁定轮与提交数，COORD-008 砍的是逐轮追加与逐步门。两轮减法
之后，流程成本的重心已经从「写」转移到「读」：每个角色切换都是新鲜上下文
会话，开工必读（AGENTS.md「必读顺序」第 1–4 步）是固定开销，随仓库文档体量
单调增长。COORD-008 §1 当时已记录该机制（「每次角色切换的新会话都要重读这些」），
但那一轮只制止了增长来源（逐轮追加），存量体积没有消化。

### 1.2 成本机制

- **每会话固定开工成本（估算）**：AGENTS.md + workflow 全文 + 状态板结构节 +
  角色细则 ≈ 3.5–5.5 万 token，未含提案/复核/证据的按需读取，未开始任何实质
  工作。一个工作项的最低角色路径（构思→接受→实现→核对轮→复核轮→收尾）约
  6 次会话，仅流程性重读估算 20–35 万 token/项；每多一轮 C/R 再加一份。
- **重复义务**：workflow §7 规则 1「所有 Agent 开工前和交付前都重新读取
  `current-status.md`」与 §6.1「开工先读当前结构……修改前仍重读待改章节」
  重叠；后者已足够，前者的「全文重读」口径在 194 KB 文件上是纯增量成本。
- **Gate-echo 的人工侧成本**：每次编辑交接行都要人工翻 Gate board 逐字抄
  token；该信息完全可由机器从同一文件派生（「可派生标识禁手写」原则覆盖
  标识本身，但没给派生入口，于是每次都要人去读源）。

## 2. 输入、输出与受影响接口

- 输入：`docs/current-status.md`（读取侧）、`docs/collaboration-workflow.md`
  §6.1/§7 规则 1、`AGENTS.md`「必读顺序」与「共享状态更新」、
  `docs/roles/chore.md` 既有压缩授权。

- 受影响接口：所有角色的开工读取路径；`tools/check_docs.py`（N4/N5 若采，

  Gate-echo 语义、blocks/releases 配对、证据门槛或授权账本语义。

## 3. 行为假设

1. 状态板结构节的定位功能不依赖篇幅：未闭义务、当前门、指针压缩后仍在，
   新鲜会话重建当前状态的能力不受损（chore 压缩标准的既有判据）。
2. 机器从同一文件派生的 Gate-echo token 与人工翻抄等价，且消除抄错类失误。
3. 常规会话对 workflow 的使用是闭集的（状态门、轮次命名、红线、停点清单），
   速查层可覆盖；全文在争议/协调/边缘情形仍可读，不构成信息丢失。

## 7. 验收条件

可证伪，逐条对应 §1.1 基线（同一台机器、同一命令复测）：

1. 第一批落地后：`sed -n '1,305p' docs/current-status.md | wc -c` 或等价
   结构节口径 ≤ **40,000 B**（基线 64,243 B 实测；该段汉字仅 4,526 字、占
   9%，主体是英文标识符与表格），且 chore 收工自检逐条确认无未闭义务、
   限定语、负结果丢失（自检记录写入当批提交信息）。达标需 N1 的对象 (a)
   与 (b) 同时执行。
2. 第一批落地后：`## Log` 节 ≤ **45,000 B**（基线 129,243 B / 1,056 行 /
   129 条 / 汉字 24,816），129 条中被压缩的每条保留结论与指针。**口径用
   字节不用行数**：`docs/roles/chore.md` 已明写"不以 Log 或单元格的物理行数
   验收；Markdown 表行通常只有一条物理行"，Gate board 即反例（27,758 字符
   仅约 40 个物理行）；起草稿的"≤ 600 行"既与该条冲突，也比 §5 N2 自己
   "降至 300–500 行"的估算更松。
3. N4 落地后：对真实状态板运行 `session_bootstrap.py <work-id>`，输出中
   全部 echo token 与 Gate board 逐字相等（工具自检非零退出即不合格）；
   篡改夹具测试修复前必失败。
4. N5 若采：`check_docs.py` 对 §0 与正文制造一处 token 不一致时拒绝提交
   （修复前必失败测试）。
5. N6 若采：对真实状态板制造一处越限（`## Log` 超 300 行，或单条超 5 行）
   时 `check_docs.py` 必须拒绝，修复前必失败测试；且落地后连续 30 天内不需
   要任何一次"为凑体量"的额外压缩提交即保持达标（阈值生效即处置，不靠
   人工巡检）。
6. **反向验收（防退化，沿 COORD-007 §7.6）**：采纳后 6 个月内若出现因读取
   口径变化导致的事故（交接文字漂移未被发现、未闭义务丢失、速查与正文不一致
   造成错误执行），必须归因到本提案的**具体某一条**；归因得到即回滚该条，
   归因不到的不作为本提案失败证据。
