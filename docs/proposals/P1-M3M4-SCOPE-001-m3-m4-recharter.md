## Problem and research value

现行 §11 按**架构层**划界：M3 = 规划层（世界系估计 + 词典序机身分
配），M4 = 感知层（丢失阶梯 L1–L2b + YOLOE 仲裁 + 遮挡实验）。设计
文本内有三条切穿该边界的硬依赖，使 M3 按现章程无法产出有效验收物：

1. **L1 是 M3 估计器的副产品，却划在 M4。** §5 的 L1 定义是"云台跟随
   纯预测；协方差膨胀"——即 §3.5 估计器在无量测时的开环传播；§3.6
   多率表 50 Hz 行本就要求"预测外推，不依赖新帧"。估计器不做 L1
   反而需要额外代码去禁用它。
2. **M3 的验收实验在现有测量载体上退化。** M3 验收是覆盖率–机身运动
   Pareto（云台-only vs 阈值式 vs 词典序）。benign SCENE-004 载体
   `C_geom=1.0` 属设计预期（`DR-P1-M2-001` N5），P1 判据
   `Pr[可见|belief] ≥ p_min` 恒满足 → 词典序机身永不动 → 三种策略
   行为全同 → Pareto 塌缩为单点，零区分度。M3 必须在可见性受威胁的
   场景上验收，而遮挡实验/困难场景义务现挂 M4/M5 名下。
3. **M4 的搜索消费 M3 的规划器。** L2b"按后验概率排序搜索视角"与
   L4 哨兵"移动到最大化未来再入可见概率的等待位"都要求机身重定位，
   执行器就是 M3 的分配层。现行顺序里该依赖方向是对的（M3 在前），
   但边界文本没有把"规划器接口是 M4 的输入"写成显式契约。

整体合并（用户提出的备选 B）救不了成本：§4.3.1 强制停点按 work item
绑定（任何改协议/语义/指标/安全/决策逻辑的 item 单独触发），合并只省
一次关闭收口，换来一个比 M2 更大的单门——后段一个返工发现会堵住前段
已完成的分配结果。RATE-003 round 3 已实证批次大小与返工成本同向。

研究价值：重划后每个门的验收实验都非退化，且里程碑边界与 §7 的消融轴
一一对应（M3′ = 机身分配轴，M4′ = 重捕获轴 + 感知轴第三档），实验
归因结构直接落在里程碑结构上——这正是 §4.7 设计审查专门检查的维度。

## Proposed behavior

纯文档/章程事项，本提案自身不改任何运行时代码。

### 1. §11 M3 行 → M3′「保持可见」（机身分配轴）

- 范围：§3.5 世界系估计器（`[x,z,vx,vz]` + 4×4 协方差；测量协方差由
  像素/姿态/地面高度不确定性传播，不用固定噪声）+ **L1 惯性滑行**
  （估计器无量测传播 + 协方差膨胀 + T1 定时器；从 M4 移入）+ §4.1
  词典序 P1/P2 判据（Phase 1 采样式/势场近似求解）+ 阈值触发式机动
  对照 + 预置机动模式。§5 阶梯表本身不改，改的只是里程碑归属。
- 验收：在 `C_geom` 有实义缺口的场景上（见 §3 前置），云台-only /
  阈值式 / 词典序三点覆盖率–机身运动 Pareto 报告 + 估计器一致性证据
  （创新性内容按 §4.2 表述纪律：机身代价称 body-motion/operational
  effort，不称 energy）。
- 显式新增一条验收前置：Pareto 测量开始前必须有**预登记的场景适配性
  核查**——评估域离线证明所选场景在系留工作空间内存在可见性余量
  （机身重定位能改变期望可见性）；核查不过则先改场景，不得在无余量
  场景上跑三策略"对比"。
- M4′ 消费的**规划器接口**（航点/速度设定值契约）在 M3′ 内早期冻结
  并单独复核，避免 M4′ 被 M3′ 尾部阻塞。

### 2. §11 M4 行 → M4′「丢失恢复」（重捕获轴 + 感知轴第三档）

- 范围：L2a 几何搜索 + L2b 路网 belief 搜索（消费 M3′ 规划器接口作
  执行器）+ L4 哨兵 + §3.3 仲裁/ReID/view-bank 全量（感知轴第三档）
  + 遮挡实验。L3 VLM 仍归 M6，不移入。
- 验收：不变——删失 MTTR、ID switch、错误重捕获率报告；在与 M3′
  共享的困难场景上执行。
- §5 v0.3 关键调整 1 的信息公平锚（L2b 与 VLM 拿同一份
  `WorldModelHandle`）在 M4′ 章程中显式重申。

### 3. 共享前置：`P1-SCENE-005` 困难场景 v1（另立提案）

- 本提案只章程其存在与门位：M2 关闭 → SCENE-005 → M3′ → M4′。
- **默认候选是评估既有困难路线，不是新建场景**：SCENE-002 道路合法
  路线实测 `C_geom=0.219562724`（UT-P1-SCENE-002-001 attempt 3，
  162.98 s），几何难度已存在；SCENE-005 的第一步是上文"场景适配性
  核查"（该路线上系留工作空间内是否有可见性余量），仅当余量不足才
  做定向修改。吸取 SCENE-003 教训：任何锚点/放置变更前先跑支撑/净空
  可行性审计。
- SCENE-005 同批收口两笔悬账：M1 验收（"参数化配置跑通；`C_geom`
  显著 < 100%"——两半证据均已存在，缺的是门板行与关闭归因；随机
  路线生成已由已接受的 SCENE-002 决定移交 M5）与 N5 的困难场景义务
  指向。M1 关闭本身是接受角色 + 用户权限，本提案仅建议记账路径。

### 4. 顺序与停点

- M3′ / M4′ 各保留一个关闭候选停点（§4.3.1 清单中的 M3/M4 行随重划
  更名）；M3′ 内部规划器接口冻结批次是额外的独立停点（改控制协议）。
- M3′ 的构思/设计工作即刻可并行（本提案 + 后续 M3′ 实现提案均为文档
  事项）；**实现启动**仍受"M2 关闭候选停点未过前不得启动依赖性新
  功能"约束，与 `P1-M2-SCOPE-001` 的收口进度衔接。

## Failure modes and resource risks

- **既有困难路线无可见性余量**：适配性核查可能证明该几何下机身重定位
  改变不了期望可见性（如遮挡全来自贴路建筑、任何合法机位都被挡）。
  此时 SCENE-005 退回定向改场景，成本上升；这正是把核查前置的理由。
- **非真值遮挡先验做脏**（OQ-1）：若先验在运行时读评估域几何，真值
  边界被击穿，M3′ 全部结果作废。缓解：先验必须离线构建 + hash 冻结 +
  复核核对物料来源；复核范围显式包含"信息来源审计"。
- **估计器协方差传播比预期难**：§3.5 要求三源不确定性传播，斜视/
  坡路误差放大已知。缓解：Phase 1 允许保守上界式传播，如实披露。
- **规划器接口早冻过早**：M4′ 搜索届时可能需要接口外能力。缓解：
  接口冻结批次含 M4′ 需求预审（L2a 扫描、L2b 视角序列、L4 等待位
  三个用例走查）。
- **资源**：本提案零代码零采集。下游 M3′/M4′ 的 Unity 会话预算在各自
  实现提案中按账本纪律另行申请，本提案不预支。
- **运动学 plant 的表述风险**：R2 已知——Pareto 的 body-motion 是
  指令域度量，不含张力/垂度动力学；论文表述沿 §4.2/R2 纪律，不称
  高保真。

## Codex review decision

### Acceptance round 1 — 2026-07-31

Decision: **ACCEPTED_WITH_BINDING_CLARIFICATIONS**

Rationale:

按研究问题重划比现有架构层划界更可证伪：M3′ 对应“能否在丢失前保持
可见”的机身分配轴，必须包含估计器无量测传播产生的 L1；M4′ 对应“丢失
后能否恢复”，消费已冻结规划器接口并承载搜索/仲裁指标。该划分保留两个
独立关闭停点，避免整体合并的大门，同时修复 benign 场景让 M3 Pareto
退化为单点的问题。用户已逐字选择结构化选项 A，授权范围覆盖此重划。

Binding clarifications（下游提案/实现按字面执行）：

1. **BC-M34-1 — M3′ 的精确边界。** M3′ 包含 §3.5 世界系估计器、
   predicted-only 无量测传播、协方差膨胀与 T1 所构成的 L1、云台-only /
   阈值式 / 词典序三策略、预置机动和规划器接口。M3′ 不实现 L2a、L2b、
   L4 状态机、完整 ReID/view-bank 仲裁或遮挡恢复实验；提供 L4 可消费的
   waypoint/HOLD 能力不等于实现 L4。
2. **BC-M34-2 — M4′ 的精确边界。** M4′ 包含 L2a、L2b、L4 状态与
   转移、完整 §3.3 仲裁/ReID/view-bank 和遮挡实验；L3 VLM 仍归 M6。
   L2b 与未来 VLM 必须消费同一版本、同一 hash 的 `WorldModelHandle`，
   不得通过信息不对称制造收益。
3. **BC-M34-3 — 阈值式对照。** 阈值式机动的触发量冻结为
   `PlatformState` 发布的**当前云台限位裕度**，不是预测时域内的离轴角、
   可见概率或 evaluator 真值。触发阈值、迟滞、解除阈值和机动方向规则须
   在任何 Pareto 数据前预注册；它可消费同一 `TargetEstimate` 生成即时
   卸载方向，但不得消费 horizon visibility optimization。
4. **BC-M34-4 — 场景适配性报告先行。** `P1-SCENE-005` 必须先评估既有
   SCENE-002 困难路线。报告至少证明：(a) 基线 `C_geom` 有实义缺口；
   (b) 系留/高度/净空约束内存在至少一个合法机身动作，使冻结目标 belief
   集合中非零测度部分的期望可见性改变；(c) 支撑/净空审计通过。任一不
   满足即返回场景设计，禁止开始三策略 Pareto 采集。
5. **BC-M34-5 — SCENE-005 不被本提案偷渡接受。** 本裁定只章程化该 ID；
   构思角色仍须提交独立提案，接受角色另行裁定，运行时改动仍须实现、
   独立复核和 Unity 验证。M1 不在本批次关闭；M1 的最终关闭需要单独用户
   授权与接受归因。
6. **BC-M34-6 — `WorldModelHandle` 是实现前硬门。** M3′ 实现提案接受
   前必须冻结物料来源、离线构建流程、schema/hash、版本、坐标系、可见性
   查询语义与信息公平规则。运行时不得读取 `CoverageEvaluator`、truth
   sidecar、逐帧目标真值或针对评估 run 生成的答案。2.5D 棱柱与走廊粗
   先验的选择本轮不代替下游设计裁定；未裁定不得写实现代码。
7. **BC-M34-7 — 规划器接口独立停点。** 在 M3′ 策略实现和任何 M4′
   依赖实现之前，先冻结版本化命令契约，至少包含 command/sequence ID、
   坐标系与单位、HOLD/velocity/waypoint 模式、issue/valid-until 时间、
   速度/加速度/系留约束处置、ACK/拒绝、stale/重复/乱序与 fail-safe
   语义。该批次单独形成稳定候选，经实现写入审计和独立复核通过后，依赖
   实现才可继续。
8. **BC-M34-8 — 统计与超参数冻结。** 确定性 M3′ 场景逐 run 报告并用
   中位数作描述，不报 95% CI；随机种子 CI 义务留给 M5。`p_min`、预测
   时域 H、阈值基线参数和策略比较顺序必须在 suitability 报告之后、任何
   Pareto 测量之前冻结；不得用 Pareto 结果反选。
9. **BC-M34-9 — 顺序门。** M3′/M4′ 构思文档可并行起草；实现顺序是
   M2 关闭 → SCENE-005 通过其自身门 → 规划器接口停点通过 → M3′ 其余
   实现与关闭 → M4′。不得以本章程接受代替任何一个停点。
10. **BC-M34-10 — 工作流文件边界。** 当前 workflow §4.3.1 的通用
    M3/M4 强制停点继续分别映射到 M3′/M4′；控制协议通则已经覆盖规划器
    接口额外停点。本接受角色不修改只读工作流基础设施；若要在该文件中
    改名，须另开有用户直接授权的协调批次。
