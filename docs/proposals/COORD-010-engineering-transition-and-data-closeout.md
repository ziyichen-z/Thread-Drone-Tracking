## 1. 问题、目标与决策摘要

用户希望优先形成有工程意义的 GitHub 开源项目，尽量利用已有数据与架构；
有时间再扩展真实数据验证、端侧优化或研究实验。已确认的使用过程是：
自然语言指定目标 → 定位 → 持续跟踪 → 丢失后恢复或请求操作者确认。

原 DATA-002 已完成采集与 S0–S5，决定性上界为 37 个双验证对象 < 60。
继续为原确认性门槛补采，不应成为工程项目的默认前置条件。与此同时，
“工程换轨”不能把不足改记为通过，也不能把已有图像、模型、协议和控制工具弃用。

本提案请求批准一个有终点的迁移批次：

1. 终止 DATA-002 的旧采集目标，不启动第二信封；保留不足结论与来源记录缺口。
2. 将 DATA-001 原 G0/D0 工作包收束为部分产物交付，旧四臂/T-G1 退出近期必做范围。
3. 原始资产保留，允许后续加工、修标和构建有版本记录的工程数据集。
4. 为新工程工作采用短任务合同、相称测试、关键停点与发布复核；不修改旧研究证据。
5. 交付工程首版范围和下一项资产适配任务说明；本批不写运行时代码、不训练、不发布。

## 5. 工程首版范围（后续工作章程草案）

首版定位：现有 Unity 车辆场景中的受限语言选目标与持续跟踪，电脑端首先可复现。
复用结构：事件触发 VLM → 有效性与帧对应检查 → SOT 接管 → 既有控制链路。
保留人工框选/确认入口；迟到结果不得直接当当前帧观测，歧义或丢失须有显式状态。

首版交付闭集：可运行示例、依赖安装说明、模型来源/版本、受支持指令说明、
人工回退、关键路径测试、固定评估集与结果、失败案例、演示、代码/依赖许可说明。
其中恢复的最低范围是报告丢失并允许重新指定；自动恢复范围由后续接口提案确定。
首版不承诺开放域理解、复杂语义搜索、实机飞行、教师增量、Jetson 性能或论文结论。

基线保留人工框选+同一跟踪器、原始模型；做微调或量化时再加入同集版本对照。
指令集、样本数、Success@IoU 的具体协议、延迟阈值和资源预算由工程任务在执行前
根据真实试读与试运行提出；本提案不凭“2 秒/帧”或任意样本数冻结合格线。

拟议发布顺序：电脑端可复现闭环 → 按短板做数据适配/微调 → Jetson 共驻实测 →
真实航拍或研究扩展。Jetson 小规模可行性探测可前移，但需独立说明设备和额度；
桌面量化结果不能替代板端实测。GitHub 公开/发布仍需用户明确授权，本文不执行。
