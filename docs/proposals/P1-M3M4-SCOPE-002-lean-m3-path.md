## 1. 问题和研究价值

### 1.1 可独立复算的几何事实（**仅目标中心、仅指向**）

以下只用 `config/scenario.default.json`
（`sha256=f9c9205249aacf7487579ca42f727c766800cc329d0523ec82a96140564a2ce3`）
的冻结字节离线算出。**它们只刻画目标中心的指向几何，不构成对 `C_geom`
的任何上界或下界**——这一限定是 revision 1 新加的，原稿缺了它。

1. **折线几何**：8 段折线闭合，周长 `212.970563 m`。
2. **路线相对锚点的水平距离**：最小 `0.500000 m`（北向直线段 `z=117.5`
   对锚点 `z=117.0` 的垂距，精确值）、最大 `69.112228 m`（顶点
   `(174.5, 62.5)`）。
3. **冻结初始悬停点 `p_hover`**（锚点正上方 25.0 m）到目标中心的最大
   离轴角 `70.113398°`，对 `45.0° + 30.0° = 75.0°` 的余量为
   `4.886602°`。

**revision 2 修正（round 2 第 2 条）**：`212.970563 / 2.0 = 106.485281 s`
这个"环周期"**不是目标车的实际周期**，原稿从 revision 0 起一路引用它，
round 1 的独立复算也只复算了折线本身，双方都漏了实际相位律。

`LoopTargetVehicle.Step` 的真实语义：`Configure` 置 `position = route[0]`、
`waypointIndex = 1`；每步取当前目标顶点，若水平距离 `< 0.5 f` 则**推进
顶点索引并直接 `return`（该步不移动）**，否则沿单位方向走 `speed·dt`。
因此目标既在每个顶点前 0.5 m 切弯，又在每次换段时**停顿整整一步**。

以 `dt = 0.2 s`、`speed = 2.0 m/s` 精确复现该语义，实测：

| 量 | 折线假设 | 实际相位律 | 差 |
|---|---|---|---|
| 环周期 | `106.485281 s` | **`107.800000 s`**（539 步） | `+1.314719 s` |
| 每环行程 | `212.970563 m` | **`212.400000 m`** | `−0.570563 m` |
| 换段停顿 | 0 | **8 步**（每顶点 1 步） | — |

本稿全部量改用 **539 个相位步、周期 `107.800000 s`**。事实 2、3 只依赖
折线顶点与锚点的静态几何，不受影响。

### 1.2 采纳 round 1 第 1 条：指向维度**不是**常值

原稿由事实 3 推出"任何合法位置都能指到 ⇒ `C_geom*(p)` 场在指向维度是
常值 ⇒ SCENE-005 的场工件被证伪"。**该推论错误，本稿撤回。**

**(a) 位置依赖。** 接受角色给出的反例经本角色独立复算，逐位吻合：h=25 m
时系留圆盘上与最远顶点**反向**的边界点 `(116.937063, 25.2, 136.316002)`
（水平半径 `24.494897 m` = `r(25)`），到最远顶点水平距离 `93.607125 m`，
离轴角 `75.046813° > 75.0°`。

本角色进一步算出一条**更强**的位置依赖，原稿同样漏了：

| h (m) | r(h) (m) | `p_hover` 列上 | 朝目标移到边界（最优） | 背离移到边界（最差） | 最差是否越限 |
|---|---|---|---|---|---|
| 8.0 | 34.073450 | 83.397184° | **77.138773°** | 85.566719° | 是 |
| 12.0 | 32.878564 | 80.149900° | **71.675969°** | 83.289563° | 是 |
| 16.0 | 31.128765 | 76.965228° | 67.157425° | 80.931214° | 是 |
| 20.0 | 28.722813 | 73.860382° | 63.656341° | 78.446453° | 是 |
| 25.0 | 24.494897 | **70.113398°** | 60.737201° | 75.046813° | 是 |
| 28.0 | 21.000000 | 67.945253° | 59.801766° | 72.738745° | 否 |
| 32.0 | 14.177447 | 65.155154° | 59.778818° | 68.983160° | 否 |

在 `h = 8.0 m`（合法最低高度），**即使把机身移到朝向目标的边界**，最远
顶点仍为 `77.138773° > 75.0°`——该高度层上不存在任何能指到最远顶点的
合法位置。指向可达性随高度剧烈变化，这本身就是一个真实的机身分配维度。

**(b) 谓词依赖。** 75.0° 这条线是对**目标中心**说的。`CoverageEvaluator`
判的是 15 个采样点（8 个包围盒角 + 中心 + 6 个轴向极值）中至少 3 个
（`visibleCount / 15 >= 0.2`）在视锥内**且**未被遮挡。中心在视锥内**不
蕴含** ≥3/15 通过：`if (!inFrustum) continue;` 使出锥采样点不进分子，
而分母恒为 15。在 70° 离轴、目标位于画面边缘时，包围盒的部分采样点很可能
出锥。

**结论**：机身分配的收益可以同时来自**指向**与**遮挡**，原稿"只剩掠射
遮挡"的论断不成立。本稿不再以"证伪"为由请求 supersede，改用完整的
BC-M34-4 义务对映（§8.1）。

### 1.4 四个决策量（round 1 第 2 条）

revision 1 拆出四个量，但把**不施加转率**的 `C_hover` 与**施加
`120°/s`**、从 `LookNadir()` 起步的 `C_reachable` 直接相减——那个差里混
着云台动力学，不是纯机身收益，且 `C_hover ≤ C_reachable` 可以合法失败。
round 2 第 1 条判得对，本稿改正。

**revision 2 的量表**。所有量共用同一 15 点谓词 `V(p, q, t)`（`q` 为云台
姿态）、同一相位律（§1.1，539 步）、同一 `dt = 0.2 s`：

| 量 | 云台动力学 | 机身 | 用途 |
|---|---|---|---|
| `C_hold_dyn` | 有限转率，起始 `LookNadir()` | 钉在 `p_hover` | **处分基线**（M3′ 云台-only 的实际对照） |
| `C_body_dyn` | **同上，逐字相同** | §3.3 站点图求出的可行轨迹 | 处分对照 |
| `C_instant_grid` | 同上 | 每步瞬移到站点集合内最优站 | 上界（物理不可达） |
| `C_hover_oracle` | **无转率**，瞬时指向 | 钉在 `p_hover` | **仅作反天花板上界**；不得再称"实际基线" |
| `C_static_grid` | 有限转率，同上 | 站点集合内最优**固定**站 | 诊断：单纯换个固定机位的收益 |

**处分依据改为 `G_body = C_body_dyn − C_hold_dyn`**（round 2 第 1 条）。
两者唯一的差别是机身轨迹，云台律、初始姿态、步长、相位律全部逐字相同，
所以 `G_body` 是纯机身可归因量。

必要自洽关系（不满足即实现有错，fail closed）：

```text
C_hold_dyn ≤ C_body_dyn ≤ C_instant_grid
C_hold_dyn ≤ C_static_grid ≤ C_instant_grid
C_hold_dyn ≤ C_hover_oracle
```

前两条按构造成立：`C_instant_grid` 与轨迹**在同一站点集合上取值**（§3.3、
§3.5），且该集合显式含 `p_hover`，所以瞬移最优不可能劣于任何可行轨迹或
任何固定站。revision 1 的 `C_reachable ≤ C_instant_grid` 之所以能失败，
正是因为上界用 4 m 网格、轨迹用 1 m 量化（round 2 第 3 条），本稿已消除
该不一致。

第三条来自 `C_hover_oracle` 的云台无转率、无初始 acquisition 代价。

### 1.5 BC-M34-4(b) 的可证伪表述

BC-M34-4(b) 要求"存在至少一个合法机身动作，使冻结目标 belief 集合中
非零测度部分的期望可见性改变"。

revision 1 用 `T⁺ = {t : max_p V(p,t) > V(p_hover,t)}`，取的是**逐时刻
瞬移最优**位置，而 `C_reachable` 来自另一条轨迹——两者不是同一个动作，
"对应最优位置可提前到达"也没有定义一个在整个区间内持续有效的动作。
round 2 第 2 条判得对，本稿改正为**绑定到同一条被选中的可行轨迹**：

设 `(p_DP(t), q_DP(t))` 是 §3.3 求出并写入工件的那条轨迹，
`(p_hover, q_hold(t))` 是同云台律的 HOLD 对照，则

```text
T_reach⁺ = { t : V(p_DP(t), q_DP(t), t) > V(p_hover, q_hold(t), t) }
```

两条**同时**成立才满足 BC-M34-4(b)：

- **测度条件**：`μ(T_reach⁺) ≥ γ_min = 0.05`（相对周期 `107.800000 s`）；
- **驻留条件**：`T_reach⁺` 含至少一个长度 `≥ τ_min = 3.0 s` 的连续区间。

因为 `T_reach⁺` 直接由那条轨迹定义，"能否到达"不再是额外论证——轨迹
本身就是可行性证据。两条都记入工件，连同 `p_DP(·)` 全序列。

## 3. 算法或行为假设

### 3.1 谓词必须与 evaluator 逐字同构

`V(p, t)` 必须复现 `CoverageEvaluator.EvaluateVisibility` 的全部判据：

1. 15 点采样：8 个包围盒角 + 中心 + 6 个轴向极值（`VisibilitySamples`）；
2. 视锥测试：`WorldToViewportPoint` 后 `z > 0 && x,y ∈ [0,1]`；出锥点
   `continue`，**不进分子，分母恒为 15**；
3. 视线测试：`Physics.RaycastAll(origin, dir, distance − 0.05f, ~0,
   QueryTriggerInteraction.Ignore)`，命中目标自身或其子物体则跳过，其余
   任意命中即判遮挡；距离 ≤ 0.05 m 直接判通；
4. 判定：`visibleCount / 15 >= 0.2`；
5. **时间加权**：`c_geom = geometricDuration / totalDuration`（evaluator
   按 `DeltaSimulationSeconds` 加权，不是帧计数比）。E1 使用等步长采样，
   权重恒定，须在工件中显式记录该步长。

允许的唯一优化是早退（布尔判定只需 3 个可见采样点）；需要输出
`visible_sample_fraction` 的位置不得早退。

**冻结的目标相位律（round 2 第 2 条）**：精确复现
`LoopTargetVehicle.Step`，而**不是**弧长均匀 belief。理由是决策量必须
描述 evaluator 实际测量的那辆车，而 evaluator 测的就是这个 `Step`。冻结
项：`Configure` 的初值（`position = route[0]`、`waypointIndex = 1`）、
`deltaTime = 0.2 s`、`speed = 2.0 m/s`、换段判据 `delta.magnitude < 0.5f`
（含"推进索引后该步不移动"的停顿语义）、`delta.y = 0f` 的水平投影。
一环 539 步、`107.800000 s`。

**冻结的步内次序（round 2 第 2 条）**：每步严格按

```text
1. 目标按 LoopTargetVehicle.Step 前进（或停顿）
2. 机身按 §3.3 的 epoch 计划更新位置
3. 云台按 §3.2 的律转动
4. 评估 V(p, q, t)
```

任何其他次序都会改变 `V`，因此该次序是门语义的一部分，不是实现细节。

### 3.2 oracle pointing 的精确定义

云台指向当前目标真值中心，受 `maximum_off_nadir_deg = 45.0` 硬限，超限
时**钳到限位边界**（与 `TetheredGimbal` 现有行为一致）。

**转率 `slew_rate_deg_per_second = 120.0` 在 §1.4 表中除
`C_hover_oracle` 外的全部量上逐字施加**，初始姿态一律 `LookNadir()`
（round 2 第 1 条）。`C_hover_oracle` 是唯一的无转率量，只作反天花板
上界，不参与 `G_body`。

若 oracle pointing 被实现成"无限位地指向目标"，`C_hold_dyn` 会被高估、
`G_body` 会被低估，结论偏向"场景没救"。限位钳制必须有单独测试。

### 3.2.1 云台姿态为何不必进入图的状态键

round 2 第 1 条要求：DP 若保留有限转率，云台方向必须进入状态/去重 key，
否则两条以相同机身状态到达但云台姿态不同的路径会被错误合并。

本稿用一条**可复算的上界**免掉这个状态维，而不是忽略它：

- 视线角速率 `≤ v_rel / d_min`。相对速度上界
  `v_target + v_body = 2.0 + 4.0 = 6.0 m/s`；视线距离下界为垂直分离
  `minimum_altitude_m = 8.0 m`（目标在 `y = 0.2`，机身在锚点上方
  `≥ 8.0 m`）。
- 故角速率 `≤ 6.0 / 8.0 rad/s = 42.971835 °/s`，每 `dt = 0.2 s` 需转
  `≤ 8.594367°`，而云台每步可转 `120.0 × 0.2 = 24.0°`。

**`8.594367° < 24.0°`，恒有裕度**，因此除首步 acquisition 外，云台在
每步末都精确落在"当前几何所要求的姿态"上——它是 `(p(t), target(t))`
的确定函数，与到达路径无关。首步 acquisition：`t = 0` 时机身在
`p_hover`、目标在顶点 0，离轴 `atan(6.519 / 25.0) = 14.62° < 24.0°`，
一步内完成，且两个对照的首步完全相同。

**这条不是假设，是必须被实现验证的断言**：E1 每步记录"所需转角"，一旦
任一步 `> 24.0°`，立即 fail closed 并报 `SLEW_BOUND_VIOLATED`——那说明
上界推导有误，此时姿态确实必须进状态键，本门作废重裁。

### 3.3 `C_body_dyn` 轨迹的唯一算法，运行前冻结（round 1 第 3 条 / round 2 第 3 条）

**revision 1 的稠密 DP 不可执行，本稿整体替换。** 复算如下（round 2
第 3 条）：位置 1 m 量化在系留工作空间上给 `60,711` 个位置状态，速度
0.5 m/s 量化在 `|v| ≤ 4` 上给 `2,109` 个，合计 **`128,040,085` 个状态**；
× 539 步 × 27 候选加速度 = **约 1.84 万亿次转移**；仅轨迹回溯就需
`539 × 128 M × 4 B ≈ 270 GB`。这不是"贵"，是不可执行。原稿的
"8.3 M 射线"资源估算只算了 4 m 场，完全没算 DP。

**替换为时间展开站点图**。关键结构性观察：可见性场的计算（昂贵，需射线）
与轨迹搜索（廉价，纯查表）可以分离——搜索**复用**已算好的场，不新增
任何一条射线。

| 项 | 冻结值 |
|---|---|
| 站点集合 `S` | §3.5 的 4 m 点阵 ∪ `{p_hover}`，共 **1,040** 站；全部先过 §3.4 净空 |
| 初始站 | `p_hover = (132.0, 25.2, 117.0)`，速度零、云台 `LookNadir()` |
| 评估步长 | `dt = 0.2 s`，一环 **539** 步（§1.1 实测相位律） |
| 机身决策 epoch | `dt_body = 2.0 s = 10` 个评估步；一环 **54** 个 epoch（53 个满 10 步 + 1 个 9 步） |
| 允许转移 | 站 `i → j` 当且仅当 `dist(i, j) ≤ 4.000 m`（含 `i = j` 的驻留） |
| 转移可行性依据 | **rest-to-rest 保守判据**：`a_max = 4.0 m/s²` 下，2.0 s 内加速 1 s（2 m，达 4 m/s）再减速 1 s（2 m）= **恰好 4.000 m**，两端速度为零。故每 epoch 至多走一格，且 epoch 边界上机身静止——速度因此**不必进入状态** |
| 转移期可见性 | 该 epoch 的 10 个评估步一律记 `min(V(i,t), V(j,t))`（驻留时 `i = j`，即 `V(i,t)`）。这是保守下界，且只用已算好的场 |
| 净空 | 站点与转移路径均按 §3.4 审计；不合法的站与边**从图中删除并计数**，不得沉默剔除 |
| 目标函数 | 最大化 `Σ_t V(p(t), q(t), t) · dt`，即最大化 `C_body_dyn` |
| 求解 | 时间展开图上的前向最长路径（DAG，按 epoch 分层，逐层松弛） |
| 平局规则 | 依次比较：累计目标值 → 更小的累计机身位移 → 字典序最小的 `(x, y, z)` |

规模（预注册资源上限，见 §3.5）：**56,160 个时间展开节点、292,032 条
边、值函数加回溯约 0.45 MB**。相对 1.84 万亿转移降了约七个数量级。

**代价与诚实表述**：站点离散、每 epoch 一格、转移期取 `min`、epoch
边界静止——四项都是保守的，所以 `C_body_dyn` 是**下界**，`G_body` 也是
**下界**。这必须写进工件与任何论文表述。下界为正即义务达成；下界为零
**不**等于真实余量为零，此时处分为 `NO_BODY_HEADROOM` 但须在报告中明确
标注其为下界结论（§5.1 第 4 行）。

### 3.4 合法工作空间必须含机体与缆绳净空（round 1 第 4 条）

原稿在精简时丢掉了 SCENE-005 的空中工作空间审计，**本稿恢复**。地面
route-corridor 审计不能代替空中机体与缆绳审计。

每个进入 `max_p`、`mean_t` 或 `C_body_dyn` 轨迹的站点 `p` 必须同时通过：

1. **机体膨胀净空**：以 `p` 为心、半径 `ρ_body` 的球与评估域碰撞集合
   无交；
2. **缆绳净空**：锚点 `(132.0, 0.2, 117.0)` 到 `p` 的线段，以半径
   `ρ_cable` 膨胀成胶囊，与评估域碰撞集合无交；
3. **转移净空**：`C_body_dyn` 的每一段转移路径按同样两项做连续或保守
   离散审计（保守离散指按 ≤ `0.5 · min(ρ_body, ρ_cable)` 的步长细分）。

**revision 1 写的"与全部代理无交"会把合法工作空间判成空集**（round 2
第 4 条）。复算：锚点 `y = 0.2`，`ρ_cable = 0.25` ⇒ 胶囊下缘在
`y = −0.05 < 0`，而 `EvaluationOcclusionGeometry` 会为道路/地面
MeshRenderer 建代理，所以**每一个机位**的缆绳胶囊都与自己的支撑面相交。
本稿改正。

冻结值（运行前冻结，禁止结果后调整）：

| 参数 | 冻结值 | 依据 |
|---|---|---|
| `ρ_body` | `1.0 m` | 机体外廓加安全余量 |
| `ρ_cable` | `0.25 m` | 缆绳外廓加安全余量 |
| `d_trim` | `1.0 m` | 见下 |
| 碰撞集合 | `EvaluationOcclusionGeometry` 构建的全部代理，排除运行时 actor 根 | 与 evaluator 遮挡集合同源 |
| layer mask | `~0` | 与 `HasClearLineOfSight` 同源 |
| trigger | `QueryTriggerInteraction.Ignore` | 同上 |
| 切触判定 | 接触即视为相交（`≥ 0` 穿透判违规） | 保守 |

**锚点支撑面的有界接触例外**（round 2 第 4 条，只在锚点端点附近生效）：

1. E1 在锚点 XZ 处向下射线实测支撑面，记录其**碰撞体实例 ID**与顶面
   高度，写入工件；查不到唯一支撑面即 fail closed，不得回退到"按名字
   排除地面"。
2. 缆绳胶囊测试**跳过自锚点起 `d_trim = 1.0 m` 的线段**；在该修剪段内，
   **只有第 1 步识别出的那个实例**被豁免，命中任何其他碰撞体仍判违规。
3. `d_trim = 1.0 m` 的依据可复算：最低仰角出现在 `h = 8.0 m` 的最大水平
   伸展处，`atan(8.0 / 34.073450) = 13.212980°`，`sin = 0.228571`。于是
   修剪终点处胶囊下缘离地
   `0.2 + 1.0 × 0.228571 − 0.25 = +0.178571 m > 0`，即修剪段之外的胶囊

**禁止**全局排除整个支撑物、同名地面或整个 layer——那会同时抹掉真实的
建筑与树木遮挡。

**未通过者不得进入任何最大值、均值或轨迹**，且必须在工件中分类计数
（机体拒绝 / 缆绳拒绝 / 转移拒绝）——沉默剔除等于悄悄改变工作空间定义。

## 6. 基线、消融、失败模式和资源风险

### 6.1 基线与对照

E1 自带四条内部对照，无需额外采集：

- **天底诊断**（F4）：对照档案 `0.219562724`，量化"云台不动"的代价；
- **`C_hold_dyn`**：M3′ 云台-only 策略的**实际**基线（有限转率、机身
  不动），也是 §11 M1 退出判据的候选数字；
- **`C_hover_oracle`**：无转率上界，量化云台动力学本身的代价；
- **`C_static_grid`**：oracle 静态布站，量化"选个更好的固定机位"的收益；
