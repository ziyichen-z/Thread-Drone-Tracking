## Problem and research value

设计 v0.3.10 §11 的 M2 行把"由新 ID 继任协议完成冻结 5/20 Hz 对比"写进
了 M2 的内容列，因此 M2 关闭在事实上被一个 20 会话的配对率研究
（`P1-M2-RATE-003`：scouting 1 + 标定 6 + probe 1 + formal 12）阻塞。
但按仓库自己的文档，这个对比的证据价值有三重上限：

1. **§3.6 原文**："对比只作闭环诊断，不声称单独识别采样与自运动因果。"
   它按章程就不能产出因果主张；
2. **`DR-P1-M2-001` N3**：确定性场景下 N=3 是伪复现件，"不作方差/CI
   依据"，固定顺序混杂必须披露——即 20 会话跑完也不产生置信区间；
3. **N5**：全部测量在 benign SCENE-004 载体上（`C_geom=1.0` 属设计
   预期），帧率差异的区分度先天受限。

同时，帧率不在 §7 的三条正交消融轴（感知/机身分配/重捕获）中的任何一条
上；它在设计中的位置是 §10 R3 风险处置 + §3.6 "结果分帧率报告"。而承载
论文核心主张（§1：tether-aware 可见性 belief 建模 + 云台/机身控制分配）
的 M3 至今零提案、零代码。三代率战役（RATE-001/002/003）已占仓库代码
改动约 40%（17,224 行，按 git numstat 归类），正式测量数据为 0/20 会话。

研究价值：把 M2 从"完成一个自我声明为诊断的对比"改为"以已有云台-only
基线曲线 + 诚实负结果关闭"，释放约 20 次用户 Unity 实测会话与三代协议
维护面，把预算转向 M3。M2 的验收列（"云台-only 在新指标下的基线曲线；
关闭前仍需 DR-P1-M2-001"）不变，且已有证据可满足。

## Proposed behavior

这是纯文档/范围事项，不改任何运行时代码、协议或指标定义。

1. **§11 M2 行内容列修订**：删除"再由新 ID 继任协议完成冻结 5/20 Hz
   对比"的关闭前提地位，改为："分帧率如实报告已有曲线；同追踪器的受控
   跨帧率对比降级为 M5 敏感性分析的可选轴，由用户届时显式启动"。
   验收列不变。
2. **M2 关闭证据基**（全部为已存在或已在途的证据，不新增采集）：
   - `P1-TRACK-001`：5 Hz CSRT follow/nadir 全程曲线（DONE；
     `C_track=0.00296718` / `0.0311135`，诚实弱基线）；
   - `P1-TRACK-002`：NanoTrack-v2 共享 30 s pilot（DONE）;
   - `P1-DETECT-001` qual-3：20 Hz NanoTrack + 三门载体 150.0036 s 曲线
     （`C_track|geom=0.920428`，零 LOST/gap/reinit；接受角色定性在途，
     见 Open questions OQ-2）；
   - RATE-001 `CLOSED_PROTOCOL_INVALID` 与 RATE-002
     `TERMINATED_AT_DECISION_A` 作为**如实报告的负结果/过程结果**进入
     M2 叙述（RATE-002 的三个 admissible 20 Hz follow 复制件可作
     困难路线 20 Hz 数据点引用，须带 N3 限定）；
   - `DR-P1-M2-001` N1/N2/N3/N5 四条表述义务逐条核对（义务本身不变）。
3. **帧率表述义务**（进论文与 M2 关闭叙述）：5 Hz 曲线来自 CSRT、20 Hz
   曲线来自 NanoTrack 载体，二者追踪器/场景/协议不同，**不可比**；受控
   同追踪器跨帧率对比未完成，三次战役按各自预登记协议终止；不得作任何
   跨帧率因果或量化结论。
4. **RATE-003 处置**：batch 1/2 的复核证据、冻结参数（150.0 s 时域、
   BC-R3-2 计 4 暂停、per-slot cap 3、BC-DRB-1..7）与全部机械**原样
   保留、不废除**——它们是 M5 可选帧率轴的现成资产。20 会话 0c 预算
   标记为未消耗；未来任何会话须按账本纪律重新授权，不自动继承。
5. **DR 有界重开**：本修订触发 `DR-P1-M2-001` 自我登记的 re-open 条件
   （"M2 关闭叙述/测量语义变化"）。提案要求的处置是一轮**范围限定于
   修订后关闭口径**的追加轮，不重开 B1/B3 等已闭合发现。

## Failure modes and resource risks

- **qual-3 定性非 PASS**：证据基退化为 TRACK-001 曲线 + 负结果；M2 仍
  可按验收列关闭（云台-only 基线曲线存在），但 20 Hz 强曲线缺位须在
  叙述中如实声明；是否接受该弱化由用户裁定。
- **DR 追加轮拒绝**：见验收条件 2 的证伪分支。
- **审稿风险**："未完成受控帧率对比"可能被问。缓解：帧率不在贡献主张
  上；三次终止按预登记协议如实报告本身是过程可信度证据；M5 敏感性轴
  保留补做通道。
- **资源**：释放约 20 次用户 Unity 会话；新增成本为一轮接受批次 +
  一轮有界 DR 追加轮，零新代码、零新采集。
- **不可逆性**：本提案不删除任何文件/数据/机械，全部决策可通过再次
  修订 §11 撤回；唯一消耗品（run ID、0c 预算）均不动用。

## Codex review decision

### Acceptance round 1 — 2026-07-31

Decision: **ACCEPTED_WITH_BINDING_CLARIFICATIONS**

Rationale:

M2 的验收列要求的是“云台-only 在新指标下的基线曲线”，不是必须完成一个
同追踪器的 5/20 Hz 因果比较。RATE-003 即使完成，也只能给出确定性、固定
顺序、benign 载体上的配对诊断；把它继续设为 M2 关闭前提，会用 20 次会话
购买一个设计本身不允许上升为因果主张的结果。现有 TRACK-001/002、
DETECT qual-3 曲线与 RATE-001/002 的诚实负结果足以构成“已有基线 + 明确
缺口”的关闭证据基，前提是不可比性、停止规则和场景局限逐字披露。

本接受只改变 M2 的关闭证据基，不把 M2 立即标成 `DONE`，不撤销历史
verdict，不改任何指标、协议或运行制品，也不把 RATE-003 的未执行结果
写成已完成。

Binding clarifications（实现/关闭角色按字面执行）：

1. **BC-M2S-1 — 选择 D2。** M2 关闭采用零新会话路径；不附带 OQ-1 的
   两槽位诊断，不要求 RATE-003 batch-2 Unity 套件复跑，也不启动 scouting、
   calibration、probe 或 formal session。任何同追踪器 5/20 Hz 新比较均为
   M5 可选敏感性轴，须由用户届时显式启动。
2. **BC-M2S-2 — 不可比性是硬表述。** 5 Hz CSRT、RATE-002 的 20 Hz
   NanoTrack、以及 SCENE-004 qual-3 的 20 Hz NanoTrack + 三门载体在
   tracker、场景、协议或控制条件上不同。M2 关闭与论文文字必须明确写出：
   “受控同追踪器跨帧率对比未完成；现有曲线不可用于估计帧率效应，也不
   支持任何跨帧率定量或因果结论。”不得用并列表格、差值或比例暗示比较。
3. **BC-M2S-3 — qual-3 的引用边界。** `P1-DETECT-001` qual-3 已由接受
   角色判为 `PASS`，可作为 benign 20 Hz 载体曲线引用；该 run 没有
   REANCHOR，只关闭 DETECT 验收 6/7。它不得补写 DETECT 验收 4 的困难
   场景背景锁定/reseed 证据，也不得关闭 N5 的困难场景义务。
4. **BC-M2S-4 — 精确证据映射。** M2 关闭检查单至少逐项链接：
   `docs/evidence/P1-TRACK-001-implementation.md`、
   `docs/evidence/P1-TRACK-002-implementation.md`、
   `docs/evidence/P1-DETECT-001-qualification-attempt-3.md`、
   `docs/reviews/P1-M2-RATE-001.md`、
   `docs/reviews/P1-M2-RATE-002.md`、
   `docs/design-reviews/DR-P1-M2-001.md` 与
   `docs/unity-test-log.md`。路径缺失、verdict 漂移或数字不一致即不得关闭。
5. **BC-M2S-5 — DR 先于关闭。** 本设计修订触发
   `DR-P1-M2-001` round 3 自登记的重开条件。独立审查者须追加一轮，只审
   修订后的 M2 关闭口径、BC-M2S-2/3/6 和证据映射；verdict 必须为
   `DESIGN_AUDIT_PASSED` 或 `PASS_WITH_NOTES`。在该轮落地、用户另行授权
   M2 里程碑关闭之前，M2 保持开放。
6. **BC-M2S-6 — N1/N2/N3/N5 原样落字。** 关闭叙述必须同时写明：
   (a) R1′ `0.2496313751 < 0.25` 的余量小于 run 间抖动，R2′ 才是停止的
   稳健依据；(b) R2′ 的约 `0.8475` 按已审计近似分为约 `0.390` 的几何
   不可见期发布与约 `0.458` 的可见期漂移，不称“85% 漂移”；(c) 确定性
   N=3 不提供方差/CI，且固定顺序时间混杂存在；(d) SCENE-004 是
   `C_geom=1.0` 的 benign carrier，困难场景义务转交 SCENE-005/M3′/M4′，
   不得写成已完成。
7. **BC-M2S-7 — RATE-003 与 0c。** RATE-003 的代码、冻结参数、复核和
   历史工件原样保留，状态改为 deferred optional M5 asset，不删除、不
   反向改写。20 次名义 0c 会话截至本裁定为 0/20 消耗；原账本条目保留
   历史效力，但不自动授权改变后的 M5 敏感性范围，未来启动须重新取得
   明确用户授权，BC-R3-2、每槽上限和条件性 0b 仍不被豁免。

Required revisions: **None before design acceptance.** 独立 DR 追加轮和
最终关闭检查属于接受后的门，不是把本提案退回构思角色的修订要求。

  说明而不删除历史；

  N1/N2/N3/N5 与 DR round-4 门。
