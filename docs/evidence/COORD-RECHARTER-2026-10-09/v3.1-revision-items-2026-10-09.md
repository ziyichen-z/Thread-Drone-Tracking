# 骨架 v3.1 修订清单（2026-10-09）

来源：用户转来的两份外部审查（对 v3 的 11 条细节问题与 8 条补充），经本 supervisor 会话逐条核对后的处置。**v3 仍是基线文本；本清单与 v3 冲突处以本清单为准；不再扩写骨架。** 标「改导出」的条目决定回放测试那一次 YOLO 加载必须导出什么，回放设计前必须落实。

## A. 会改变行为，冻结前改

| # | 问题 | 处置 | 改 v3 哪里 |
|---|---|---|---|
| A1 | 四门只防错跟，不防该跟不跟；「竞争」未定义；占位 R_floor 下运动门半径约 3 m，0.4 s 内目标只移 0.8 m，运动门分不开目标与路边停车，实际只剩唯一性在起作用 | 采纳。加「门 0 排除」：t0 之前与目标同帧各有真实检测、且自身地面位置连续的轨迹，逻辑上不可能是目标，从候选与竞争者中一并排除。剩余候选用最优与次优的累计 NIS 之差做裕度检验，决策时仍分不开才锁 DISPUTED。DISPUTED 触发条件保持「身份连续性存在无法消解的竞争」，不得简化为候选数大于一 | §6.2 |
| A2 | 99% 名义覆盖意味着每门每百帧误拒一次，约每 10 s 一次 TENTATIVE 加显式 hold；原 ID 重过门后回 SUPPORTED 需 1 帧还是 N_adopt 帧未写 | 采纳。原 ID 在窗口内重新过门且无竞争：1 帧回 SUPPORTED；新 ID 需 N_adopt。误 TENTATIVE 率是待标定量 | §4、§6.2 |
| A3 | R-3 只量误收养率，快层缺「不能靠多拒绝把风险做低」的配对口径 | 采纳。R-3 配对报修复成功率、误 TENTATIVE 率、误 DISPUTED 率 | §9 |
| A4 **改导出** | 框底中点落在车身近相机一侧边缘，交地面后比车中心近约半个车身且随朝向变化，R 被撑大；用框中心射线交 z≈0.75 m 平面在 12 m 与 25 m 处偏差 <0.1 m。look_at 对准框底中点使框中心恒偏离图像中心半个框高，t_center 容差小于它则 success_condition 永不满足 | 采纳。R-4 两种量测点都算，偏差与抖动分开报；look_at 瞄准点改为候选变量，由 R-4 定 | §7、§9 |
| A5 | semantic_status 无契约：谁写、依据哪帧、单次够不够、多久失效 | 采纳。单次核验不得把操作者确认过的绑定判成 CONTRADICTED，只进界面提示；CONTRADICTED 需两次独立输入形式一致才动授权；失效期 = 来源帧年龄超 T_repair | §4、§10 |
| A6 | 持久任务等待期处于「目标不存在」区，实测 21% 硬给框；温度 0 下相邻帧输出高度相关，同一辆错车会被反复提出 | 采纳三样：任务内拒绝记忆（被拒 track_key 不再提案）；候选集未变不重查；第二份证据换输入形式（候选裁剪放大，VLM 报颜色与车型，程序比对谓词） | §5.4 |
| A7 **改导出** | 身份时限按墙钟会使同样帧内容因处理晚 100 ms 得出不同身份结论；共驻后快层延迟尖峰正好落在 VLM 忙时 | 采纳。证据资格只看 frame_id（f0 之后 T_repair 帧以内的观测都算），处理是否及时只影响控制授权；逐帧日志加 vlm_busy 标志 | §8、§12 |
| A8 **改导出** | 未关联原始检测必须进历史：BYTETracker 新轨迹要下一帧再匹配才激活，输出只含已激活轨迹（ACQ-001 事实 19 已核），刚出现的竞争者第一帧不可见，N_adopt 晚一帧起算；探针分「漏检」与「挑错」也需要这一列 | 采纳。历史契约加原始检测列；回放导出必须含逐帧原始检测 | §7、§12 |
| A9 | 新捕获时 TargetBelief 初始化未写；10-08 丢失发生在绑定后第 4 帧，正是速度估计最差时 | 采纳。INITIAL / USER_RESELECT / ATTRIBUTE_REPLACE 都用 §7 同一套回放把滤波器从 k 跑到 N 再提交，不单点重建 | §6.3、§7 |
| A10 | 未提交候选不得驱动云台：OBSERVED + TENTATIVE 行的「观测估计」实际让云台追未提交候选，绕过不变量 2 | 采纳。OBSERVED 定义为「belief 被已接受观测更新」，不是「画面里有框」。修复期间云台只按原已绑定目标的预测估计、在 T_pred 与协方差上限内追视；候选观测只进有界修复证据缓冲（候选键、观测引用、门限结果、版本、截止）。撤权条件（取消、失效、几何无效、争议、语义冲突）优先于一切 OBSERVED 行 | §4、§5.2 |
| A11 | 授权表不是全函数：缺 PREDICTED + DISPUTED/BROKEN、年龄在 T_pred 与 T_repair 之间、geometry_valid 为假；按 §4 的边 PREDICTED + SUPPORTED 不可达；行间优先级未写 | 采纳。表改为全函数并写优先级；§14 加两条：枚举全部状态组合每格恰命中一行；任一状态变差授权不升 | §4、§14 |
| A12 | 发布前复核与写出可被 STOP 穿插：旧 FOLLOW 检查通过后暂停，STOP 写 hold，旧 FOLLOW 恢复后覆盖 | 采纳。控制发布单写者；最终授权检查、命令写出、STOP 处理串行；STOP 生效后旧授权的 FOLLOW 不得在其后完成发布。commit_binding 须定义 follow() 失败或抛异常时的回滚 | §5.2、§6.1、§14 |
| A13 | T_pred 取可用时长 p90 方向反了：到 p90 时约 90% 样本已失效 | 采纳。改为生存界 P(D > T_pred) ≥ 1 − ε_pred；定义「首次失效」而非末刻 IoU；片段结束仍可用的样本按删失处理 | §9 R-1 |

## B. 定义未闭合，文字修订

| # | 处置 |
|---|---|
| B1 | phase 只留任务生命周期 {WAITING, ACQUIRING, TRACKING, DONE, CANCELED}，PREDICTING/DISPUTED/LOST 由 belief 派生。DONE 只对用户批准的有限任务生效；持续跟随任务达到居中条件只记捕获达标事件，继续 TRACKING |
| B2 | TaskSpec 合法性扩到 selector × activation × binding_mode × on_loss：点击 → 只能 INSTANCE + NOW；谓词 → INSTANCE_AFTER_ACQUISITION 或 PREDICATE，NOW 或 WAIT；selector 二选一，点击来源的标签只作界面提示。DISPUTED 一律 ASK，on_loss 只管 BROKEN |
| B3 | §4 与 §6 统一措辞：旧 episode 内 DISPUTED/BROKEN 不得恢复为 SUPPORTED；操作者重选或 TaskSpec 已授权的谓词 REARM 可建新 episode；新 episode 初始化不视为解除旧锁存；旧 episode 关闭须有事件与原因 |
| B4 | 「多候选先问我」采用来源快照选择语义：在帧 k 完成选择，返回后验证连续到当前；绑定后后来出现的匹配对象不重开选择；界面表述为「根据该画面选择了 A」。任务承诺全画面语义时，B 的候选内 unique 不得获得全画面自动授权，证据不足保留点击确认 |
| B5 | 点击本身就是选择与批准：直接点击后不再二次确认；语言产生的提案保留一次点击确认。两条路径分开 |
| B6 | 延迟契约：L_fg = 排队 + 服务 + 回传 + 校验；在途请求是否可中断、以什么事件确认槽位释放，未确认前按不可抢占处理；T_fg 可达性在「轮询占槽时用户插入」负载下测 |
| B7 | 时间分三记：来源帧仿真/采样时间（观测顺序与物理传播）、本机接收时间（看门狗与处理延迟）、本机决策与发布时刻（有效期）。加测试：积压旧帧刚收到不得当新鲜观测 |
| B8 | P_max 改为位置创新门在地面上的最大扩展尺度 sqrt(g_motion · λ_max(S)) ≤ r_gate_max，S = H P⁻ Hᵀ + R；R 的像素、位姿、模型三项不默认独立；R-4 同时查残差是否随视角有系统偏差 |
| B9 | 「数字由测试产生」分三类：已知约束（帧率、执行器边界）、设计预算（最大可接受误绑率、用户最多等多久，由用户定）、待标定量（噪声、延迟分布、门限表现）。测试估计第三类并检查前两类能否满足；数据不能替用户决定错多少可接受 |

## C. 测试口径

| # | 处置 |

## D. 对回放测试那次 YOLO 加载的导出要求（汇总）

逐帧原始检测（A8）、全部轨迹行含 lost 池预测行、两种量测点的地面投影与残差（A4）、vlm_busy 占位列（A7，回放中恒 false 但格式留好）、合成转向帧的位姿与变换参数（C2）、首次失效时刻与删失标记（A13）、时间平均 NIS（C1）。导出格式定下来之前不申请额度。
