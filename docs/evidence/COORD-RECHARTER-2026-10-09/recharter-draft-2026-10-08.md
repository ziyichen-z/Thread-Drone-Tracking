# 重新构思草案：语义目标获取与跟随（2026-10-08）

综合三份 GPT 回答与仓库事实。第一份回答提供框架，第二份补了「任务版本号、目标管理器」但二者仓库已有，第三份不采用。本文不是提案，不改状态板；可作为构思角色起草正式提案的输入。

## 0. 结论

保留 VLM，但把它的职责从「指定时画框」和「语义身份找回」改成「把用户的语义要求映射到可见候选」和「承接持久任务」。保留 BoT-SORT 快层，但把「永久指针」改成「有证据的目标关联」，在其上加一层很薄的目标管理器。严谨性从每次操作的人工停点移到代码不变量和可复现测试里。

## 1. 三个要拆开的概念

| 概念 | 现在被谁承担 | 应该由谁承担 |
|---|---|---|
| 轨迹编号 | 指针，永不改绑 | 关联器内部可替换的编号 |
| 物理实例身份 | 隐含在指针里 | 目标管理器，用运动连续性证据维护 |
| 语义任务 | 一句描述字符串 | 目标管理器保存的任务对象：类型、约束、允许的恢复方式 |

不变量改写为：**用户选中的目标意图不能悄悄改变；内部关联可以修复，但必须有证据。** 10-08 的失败是「失去可用关联」而不是「看不见红车」，指针不改绑保护错了东西。

两种任务语义必须分开：
- **跟住这一辆**：实例任务。丢失后只有连续性证据足够才恢复，否则请求确认。点击指定缺省是这种。
- **寻找符合描述的车**：属性任务。可以接受新的匹配实例，但不能宣称它就是之前那辆。语言指定和持久任务是这种。

## 2. 主线文字草案（替换 `docs/project-background.md` §3，只能用户逐字裁定）

> 做一个边缘语义目标获取与跟随闭环，VLM 是主角：用户通过点击或语言指定目标，VLM 把语义要求映射到可见候选、承接持久任务，并对歧义与不存在显式报告；快层负责关联与状态估计，只做一轮必要修正，不做研究主张；系统在模型延迟和相机运动下完成捕获、换目标与短时重关联，对观测丢失和不可达显式反馈；部署目标是 VLM 与快层跑在 Jetson Orin Nano 8GB，Unity 留桌面机。

随之调整的四条旧约束（2026-10-08 用户口头意见后的版本）：
1. 「快层是非变量」→「快层只做一轮必要修正，额度一次 Play，不扩成跟踪研究」。用户动机：目标岗位是微调训练或 agent，快层只求能承接 VLM。检测加关联已是成熟件，缺的只是薄的目标管理层，没有现成库。
2. 「把 VLM 改为选候选 ID 一律退回」→ 允许作为探针里的对照接口 B，不是切换。含义：接口 A 是 VLM 自己输出框和 frame_id；接口 B 是检测器给编号候选框、VLM 回答第几号符合并报歧义或不存在。放宽理由：板上日志 decode 占一半以上，短输出接口单次约 0.9 s；能分开评估检测器漏检与 VLM 挑错；VLM 仍看全帧、仍做语义匹配。
3. 「不改 Unity 场景」→ 可以修正，多辆车运动是方向，具体稍后讨论。
4. 「VLM 是主角」→ 保持。含义落在三处：语言到候选的映射并显式报歧义与不存在（微调任务，有评估集与负例）；持久任务与目标管理器构成 agent 回路；量化部署到 Jetson 并用时延数据定接口。不包括两件结构上做不到的事：比点击更快地框已看见的车，逐帧维持实例身份。

## 3. 架构改动，全部落在现有代码上

> 本节为骨架 v1，已被 `architecture-skeleton-v2-2026-10-08.md` 取代；v2 把任务决策、身份连续性、控制授权拆开，改为四条记录、三个正交状态、一个提交入口、一个截止时间、两条评估函数。下文保留作历史。

### 3.1 目标管理器（新，薄）

保存：任务对象、最后一次可靠观测及其 frame_id、地面位置与速度估计及不确定性、当前关联的库 ID、是否还有足够证据继续控制。任务稳定，库 ID 可替换，状态估计持续更新。

状态与行为：

| 状态 | 控制 | 对用户 |
|---|---|---|
| 有当前可靠观测 | 正常跟随 | 正在跟踪 |
| 短时未匹配、预测可信 | 云台按预测框跟，机身 hold | 暂无新观测，正在预测 |
| 连续性证据不足 | 停止追随，有限重捕 | 正在重新确认 |
| 多候选无法区分 | 不改绑 | 身份有歧义 |
| 超时或超出搜索范围 | 明确丢失 | 无法继续确认 |

三个时间参数分开：库保留轨迹 6 s 不变；预测控制窗口初值 3 到 5 帧（0.6 到 1 s）；向用户报告「无新观测」≤ 5 帧（1 s）。10-08 的 6 秒静默正是把第一个当成了第三个。

重关联收养条件同时满足：运动预测合理、尺寸与投影变化合理、无语义冲突、无同样合理的竞争候选；丢失时间越长越保守。唯一落入范围的框不等于唯一可信的原目标。身份可疑时不得用候选生成的新描述覆盖原任务。

### 3.2 关联器前置：位姿补偿优先

帧元数据有相机位姿与内参。云台转向时相机光心近似不动，相邻帧为纯旋转，H = K_t · R · K_{t-1}^{-1}，不依赖纹理。用它把上一帧的库预测框投到当前帧再做 IoU 关联；稀疏光流降为残差校正，初版不叠加。机身移动时不再是纯旋转，用地面平面近似并保留不确定性。

云台转速限制作为辅助：转速与帧率、目标框大小、预测误差、剩余视野匹配，先验证补偿后的关联，再调平滑。

### 3.3 点击与语言入口

- 点击：带用户实际看到的 frame_id（操作网页 W2 已绑定快照），在该帧历史里找包含点的框，复用六值闭集与 follow()。缺省生成实例任务，不加常规确认。
- 语言：VLM 把描述映射到候选；唯一性功能门通过前，语言结果只提候选、不自动执行。
- 持久任务（第四种交互）：「红色轿车进入视野后跟随，多个候选先问我」。等待期每 2 到 3 s 用最新帧问一次 VLM，命中唯一且连续两次同一轨迹才绑定；等待、超时、取消由确定性任务逻辑处理。
- 所有异步请求带指令版本号；现有 epoch、designation_id、IGNORED_STALE_EPOCH 已覆盖。

### 3.4 VLM 接口由探针决定，不先重训

对照两种形式：A 现有直接选框三态；B 全帧加编号候选框，输出匹配编号与无法判断的编号。B 是一次查询一次 prefill，不是逐候选 yes/no。原始 2B 与 LoRA 版都测。样本只取难例：同类不同色、同色不同类、多个同色同类、目标不存在、检测器漏检。最终评估集另留，不用调过提示词的样本。

边界：无匹配候选不等于画面里没有目标；同一 VLM 再答「跟的还是它吗」不是独立验证，核验只提供语义证据，不取代运动连续性。

「框 → 描述」降为辅助：给点击目标贴界面标签，做属性一致性提示，不作身份记忆。

## 4. 评估：四类数字降为诊断，新增四层

| 层面 | 问题 | 记录 |
|---|---|---|
| 语义决策 | 该选谁、该不该选 | 唯一目标选对率、歧义时错误单选率、无目标时错误接受率 |
| 任务捕获 | 下令后是否真正跟上 | 从请求到正确目标连续居中 3 s 的时间与成功率，失败计入 |
| 身份与降级 | 丢关联后是否乱绑、是否及时承认 | 短时恢复成功率、错误重绑次数与持续时间、报告延迟 |
| 边缘运行 | VLM 忙时快层是否照常 | 实际帧间隔、控制状态年龄、截止违约、内存峰值、启停成功率 |

误锁率必须与接受比例、完成比例、被拒绝但本可成功的任务数一起报。离线回放只能比较检测、关联与状态机；改了控制必须回 Unity 跑。

## 5. 三轮推进

### 第一轮：VLM 旁路，修好移动目标捕获（1 次 Play）

改动闭集：目标管理器、位姿补偿、跟踪中丢失的收养触发、预测窗口发 look_at、点击入口、报告时延。推理时把两类检测统一当 vehicle，禁用 target 捷径，不重训检测器。

验收（5 Hz、640×480）：
- 点击到绑定 ≤ 1 帧。
- 离线复现 10-08 第 540 到 600 帧：转向三帧内指针保持同一 ID，或 ≤ 2 帧内由收养恢复；需加载 YOLO 一次做回放。
- 失配后 3 到 5 帧内继续发 look_at，预测框与下一次真实观测 IoU ≥ 0.3。
- 最后可靠观测到报告「无新观测」≤ 5 帧。
- 机身：初始条件把目标放在距离带外（> 14 m），验收 N 秒内进入 12 ± 2 m 带并保持；N 由规划器最大速度 4 m/s 推出并在测前固定。
- Play 中红车一圈不丢，或每次丢失都在上述窗口内恢复或报告。

### 第二轮：探针定 VLM 接口（零 Play，约 200 次板上查询）

A 对 B、原始对 LoRA、只测难例。通过线在测前固定，建议：歧义错误单选 ≤ 20%，无目标错误接受 ≤ 10%，p95 ≤ 现有 2.73 s × 1.2。不过线就让语言分支保持辅助，不用换指标绕过；过线再考虑为新任务补负例与无法判定样本训练，不重做 4,907 条。

### 第三轮：有任务价值的演示（少量场景参数化，1 到 2 次 Play）

四幕：点击捕获并换目标；转向中短时重关联；两辆相似车时系统报歧义并等确认；持久任务「红车入画即跟」。场景改动只做一项：加一辆同色同类干扰车，或让第二辆车运动。
