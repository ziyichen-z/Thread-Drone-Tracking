# 架构骨架设计讨论：项目背景与当前草案（2026-10-08，给新会话用，自包含）

请基于下面的事实，对第 6 节的骨架给出设计意见和替代方案。硬约束见第 7 节，请不要推荐新模型、云端推理、ReID 或做模型选型调研。

## 1. 项目是什么

Unity 仿真里的无人机，用 2B 小 VLM 按点击或语言指定地面车辆，快层跟踪并让云台和机身居中，对歧义、丢失、不可达显式反馈。目的是求职作品集的工程首版，目标岗位是模型微调训练或 agent 开发，所以 **VLM 是主角**，快层只求能承接。

主线文字草案（用户已口头认可，待逐字入账）：

> 做一个边缘语义目标获取与跟随闭环，VLM 是主角：用户通过点击或语言指定目标，VLM 把语义要求映射到可见候选、承接持久任务，并对歧义与不存在显式报告；快层负责关联与状态估计，只做一轮必要修正，不做研究主张；系统在模型延迟和相机运动下完成捕获、换目标与短时重关联，对观测丢失和不可达显式反馈；部署目标是 VLM 与快层跑在 Jetson Orin Nano 8GB，Unity 留桌面机。

## 2. 平台与场景事实

- Jetson Orin Nano 8GB Devkit Super，JetPack 7.2，CUDA 13.2，TensorRT 10.16，headless。Unity 跑在 MacBook Air，两机 SSH 隧道。**现状**：Play 时快层跑在 Air（Apple MPS），Jetson 只跑 VLM 服务；板上检测器 TensorRT 路径未过一致性门，共驻未测。
- 传感器 5 Hz，640×480 JPEG，每帧带相机位置、朝向、内参（fx=fy=415.7，cx 320，cy 240，垂直视场 60°）。帧保留 128 帧。
- 场景：Unity 城市街区。一辆红色轿车按固定路线 2 m/s 绕圈，其他车静止。无人机 25 m 高。系留约束已于 2026-09-30 正式放弃，改用围栏、最大速度 4 m/s、加速度 4 m/s² 边界。云台离底最多 45°，转速 120°/s。机身与云台命令 0.4 s 过期。
- Unity 与 Python 只通过一个目录下的 JSON 文件交换；真值只给离线评分，控制回路碰不到。

## 3. 现有组件（都已实现并在 10-08 跑过一次完整闭环）

**VLM（慢层）**：Qwen3-VL-2B-Instruct + LoRA r16，合并后 GGUF Q4_K_M + F16 mmproj，llama-server 单槽位、上下文 2048、跨请求不复用 KV。请求：图像在前、冻结 prompt 在后，JSON schema 约束，温度 0。输出三态：unique 给一个框 / ambiguous 给候选 / none。词表闭集九类车 × 六色。板上单次：prompt eval 0.78 s（633 token，含 300 个图像 token），decode 0.9 s（33 token，35 tok/s），服务器合计 1.65 s，会话端 2.0 s。609 行评估：单目标 +26.6 pp，格式零失败；歧义 48 行有 29 行不报直接挑一个；不存在 100 行有 21 行硬给框。

**快层**：YOLO11n 域内微调（类别只有 vehicle / target），BoT-SORT 无 ReID，相机运动补偿用稀疏光流，丢失轨迹保留 30 次更新约 6 s。常驻逐帧跑，所有车都有轨迹 ID，128 帧历史按 frame_id 索引。被跟目标是指向库 ID 的**指针，设计上从不改绑**。designate(box, frame_id_k) 在 k 帧历史里按 IoU 找 ID，六值闭集：BOUND / BOUND_COASTING / TRACK_ENDED / NO_TRACK_AT_K / AMBIGUOUS / FRAME_NOT_IN_HISTORY。TRACK_ENDED 时有 acquire 通道：用 k 帧位姿和框算世界点、云台转过去、附近唯一候选连续 3 帧收养（半径 40 px）。Mac 上单帧 update p50 29 ms。

**控制**：指针框底中点与地平面求交得世界点作云台 look_at；机身规划器按距离带出速度或 hold（目标距离 12 m，带宽 4 m），只在跟踪正常的帧出速度。每次写桥过五项发布门。

**会话与界面**：状态机 9 态（IDLE / QUERYING / AWAITING_CONFIRMATION / TRACKING / SUSPECTED / LOST / REINIT_REQUIRED / ACQUIRING / TERMINAL）；epoch、designation_id、request_id 版本机制，过期结果丢弃；VLM 查询在 worker 线程；低频 verify；本机网页把呈现快照绑定到 frame_id 与图像哈希，按钮只有发送、跳过、确认、拒绝、停止。

## 4. 10-08 实测与定位

四次语言指定全部 unique 并绑定；VLM 等待约 2 s，人工确认 2.7 到 9.4 s。唯一的移动目标在绑定后第 4 帧丢失：换目标使 look_at 跳变，云台连续三帧各转 5.2° / 3.6° / 2.8°，关联断掉，指针留在死 ID 上；之后 31 帧空框、不发云台命令、机身 hold，6 s 后库删 ID 才报失败，车 8 s 后出画。原图里车很大、无遮挡、在画面中部。整场 158 s 机身只动 0.7 m。

## 5. 已经做出的方向判断

- 三个概念要拆开：轨迹编号 ≠ 物理实例身份 ≠ 语义任务。不变量改为「用户的目标意图不能悄悄变，内部关联可修复但要有证据」。
- 两种任务语义分开：**跟住这一辆**（实例任务，丢失只靠连续性证据恢复，否则问人）与 **找符合描述的车**（属性任务，可接受新实例但不宣称是原来那辆）。
- VLM 不做逐帧身份维持，也不做「丢失后按描述找回原实例」。它做：语言到候选的映射并显式报歧义与不存在、持久任务（「红车入画后跟随，多候选先问我」）、可选的界面标签。
- VLM 接口由探针决定：A 现有直接选框三态；B 检测器给编号候选框、VLM 回答编号并报歧义或不存在。B 的输出短，decode 从 0.9 s 降到约 0.1 s，单次约 0.9 s。
- 快层只做一轮必要修正：位姿补偿优先于光流；跟踪中丢失也触发收养；预测窗口内继续发云台命令；报告时限与库保留时间脱钩。
- 场景可以改，后续会有多辆车运动。

## 6. 当前骨架草案（请重点评审这一节）

### 6.1 五层

```
操作者层   本机网页：点击(x,y,显示帧id) / 语言 / 持久任务 / 确认拒绝 / 停止，指令带版本号
任务层     目标管理器 = agent 回路（新）：任务对象 + 目标状态 + 证据等级 → 决定本帧做什么、调用谁
语义层     Jetson llama-server：接口A（现有）/ 接口B（探针）/ 标签（可选）
感知层     常驻 YOLO11n + BoT-SORT + 128帧历史（现有）；位姿补偿预测、designate_point、预测框读取（新）
控制层     look_at(观测框|预测框, 来源标记)；机身规划器按证据等级开关（改）；发布门不变
平台层     Unity 与文件桥，不动
```

### 6.2 两个数据对象

- **任务对象**，稳定，只由操作者改：任务 ID、类型（实例 / 属性 / 持久等待）、来源（点击点加帧 ID，或描述文本）、约束（歧义时问我、等待超时、是否允许换实例）、指令版本号。
- **目标状态**，每帧更新：当前关联库 ID、最后可靠观测及帧 ID、地面位置与速度估计及不确定性、证据等级、距上次可靠观测帧数。库 ID 是可替换字段。

证据等级三档：高 = 本帧库 ID 匹配且框合理；中 = 未匹配但在预测窗口（3 到 5 帧）内；低 = 超出窗口或出现竞争候选。机身只在高时出速度，中时 hold，低时停止追随；云台在高和中都发 look_at，中时用预测框并打标记。

### 6.3 每帧回路（200 ms 内）

1. 帧 N 到达，感知层检测，用位姿把上一帧各轨迹预测框投到本帧再关联，写入历史[N]。
2. 任务层查历史[N] 的当前库 ID；匹配则更新估计，证据高，按观测框控制。
3. 未匹配则进预测窗口：外推估计，按预测框发 look_at；在预测框附近找候选，过四个门：运动合理、尺寸合理、无语义冲突、无竞争；唯一候选连续 n_adopt 帧命中才改库 ID。
4. 出现竞争候选进歧义态，不改绑，按任务约束问人或继续预测。
5. 超出窗口进重确认态：实例任务只能问人；属性任务允许向 VLM 发一次重查，结果仍过第 3 步四个门。
6. 再超时进明确丢失，报告时限 ≤ 5 帧。

### 6.4 异步回路

VLM worker 返回带帧 ID k 和版本号的结果；版本旧则丢；否则在历史[k] 落到库 ID，沿 ID 走到当前帧，再进 6.3 第 2 步。持久任务是其循环版：等待态每 2 到 3 s 送最新帧问一次，连续两次命中同一轨迹才绑定。

### 6.5 六个待定关口（当前建议）

1. 目标管理器放现有会话进程内，与感知层同进程同帧。
2. 关联用图像空间（库卡尔曼加位姿补偿）；控制与合理性检查用地面空间（框底中点交地面，带不确定性）。
3. 实例任务丢失后不允许问 VLM，只能问人；操作者可显式把任务降级为属性任务。
4. VLM 单槽位串行，优先级：用户显式请求 > 持久任务轮询 > 核验；轮询在用户请求到来时作废。
5. 界面：预测框虚线加倒计时；歧义时列候选编号让人点，不弹自由文本。
6. 演示模式与测量模式只差三项：延迟注入开关、确认策略、记录粒度。

## 7. 硬约束

- 不换模型、不做模型选型、不加 ReID、不加 CLIP、不做 SAM 2 在线、不做云端推理。
- 传感器 5 Hz、640×480 不变；Unity 与文件桥不改。
- 快层只做一轮必要修正，不做跟踪研究。
- 不要复述第 3 节已有组件，不要给通用项目计划或甘特图。
